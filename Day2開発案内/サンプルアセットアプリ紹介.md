# サンプルアセットアプリ紹介

## このアプリの位置付け

サンプルアセットは、ヘルプデスクの問い合わせに対して関連文書を検索し、回答案を作成するRAGアプリケーションである。FDEとして、既存アセットを理解し、顧客課題に合わせて組み替える開発の出発点として使用できる。

> サンプルアセットの利用は必須ではない。グループのアイデアに合う場合は活用し、合わない場合は別の構成・言語・連携システムを選択してよい。

## できること

- 問い合わせチケットの一覧・詳細表示と新規登録
- 問い合わせ内容に関連する文書のベクトル検索
- 検索結果を根拠とした回答下書きの生成
- Mock構成によるAPI Key不要の動作確認
- watsonx.ai、Chromaなどへの差し替えを想定した構成

## 技術構成

| 層 | 主な技術 |
|---|---|
| Frontend | HTML / CSS / JavaScript |
| Backend | Python / FastAPI |
| Vector DB | Chroma（ローカル） |
| LLM / Embedding | watsonx.ai、または動作確認用Mock |

構成の詳細は、repositoryの[README](../README.md)を参照する。

## GitHub repository

- Repository: <https://github.com/samplename581-cpu/sample_asset>

リポジトリをブラウザーで開けない、またはCloneできない場合は、ネットワーク接続とURLを確認し、必要に応じて運営スタッフへ確認する。Gitを利用できない場合は、repository画面からZIPをダウンロードして開始できる。

## セットアップ

1. GitHub repositoryをClone、またはZIPで取得する。
2. [macOS／Windows環境構築手順](./環境構築手順_Mac_Windows.md)に従って、まずMock構成で起動する。
3. ブラウザーで <http://127.0.0.1:8000> を開き、チケット表示と関連文書検索を確認する。
4. [GUI操作ガイド](./GUI_USER_GUIDE.md)で、画面操作と回答案の扱いを確認する。
5. 必要な場合のみ、インターン運営者から提供された接続情報でwatsonx.aiへ切り替える。

詳細なコマンドとトラブルシューティングは、repositoryの[README](../README.md)と[macOS／Windows環境構築手順](./環境構築手順_Mac_Windows.md)を参照する。

## 開発時の考え方

- 先に「誰の、どの業務を、どう改善するか」をグループで合意する。
- サンプルの機能は必要な部分だけ再利用し、アイデアに合わない部分は変更または使用しない。
- データの取得・保存は必要最小限にし、個人情報や機密情報をLLM、ログ、Gitへ渡さない。
- AIの回答案は自動送信せず、参照元と内容を人が確認する。
- 変更はGitで小さく管理し、テスト、Lint、型チェックの結果をグループで共有する。

ブランチ作成、コミット、マージ、Pull Requestの最小手順は、repositoryの[Gitを使う理由と作業手順](../README.md#62-gitを使う理由)を参照する。

## 用語の補足

| 用語 | 簡単な説明 |
|---|---|
| サンプルアセット | 開発の出発点として再利用できる、サンプルのコード・データ・手順書一式。 |
| RAG | 関連文書を検索し、その内容を根拠としてAIに回答を作らせる方式。 |
| LLM | 大量の文章を学習し、質問への回答などを生成するAIモデル。 |
| Embedding | 文章の意味を、類似検索に使える数値の並びへ変換する処理。 |
| Vector DB／Chroma | Embeddingを保存し、意味の近い文書を検索するデータベース。Chromaは本アプリで使う製品名。 |
| Frontend／Backend | Frontendは画面側、Backendはデータ処理やAI連携を行うサーバー側。 |
| FastAPI | PythonでWeb APIを作るためのフレームワーク。 |
| Mock | 本物の外部サービスを呼ばず、疑似的な結果を返す動作確認用の代替実装。 |
| Repository／Clone | Repositoryはコードの保管場所、Cloneはその内容をPCへ複製する操作。 |
| SSH | 暗号化した通信で、GitHubなどへ安全に接続するための仕組み。 |
| Lint／型チェック | Lintは書式や問題のある書き方を、型チェックはデータ型の不整合を検査する。 |
