# Helpdesk Support GUI 操作マニュアル

> **前提**: `make dev` でサーバーが起動済みであること（`http://127.0.0.1:8000` でアクセス可能）

---

## 画面構成

```
┌─────────────────────────────────────────────────────────────────────┐
│  Helpdesk Support                        Provider: mock  ← バッジ  │  ← トップバー
├──────────────────────┬──────────────────────────────────────────────┤
│                      │                                              │
│  [ステータス絞り込み]  │  ← チケット未選択時                          │
│  [絞り込みボタン]     │    「左の一覧からチケットを選択してください」    │
│                      │                                              │
│  TKT-00000001        │  ← チケット選択後                            │
│  パスワードを忘れた   │    チケット詳細 + RAG 操作エリア              │
│  完了                │                                              │
│  ─────────────       │                                              │
│  TKT-00000002        │                                              │
│  VPN接続できない      │                                              │
│  対応中              │                                              │
│  ─────────────       │                                              │
│  …（一覧）…          │                                              │
│                      │                                              │
│  [さらに読み込む]     │                                              │
└──────────────────────┴──────────────────────────────────────────────┘
```

| エリア | 名前 | 役割 |
|---|---|---|
| 上部横帯 | トップバー | アプリ名 / LLM プロバイダー表示 |
| 左ペイン | チケット一覧 | Ticket の一覧・絞り込み・ページング |
| 右ペイン | 詳細 + RAG | 選択 Ticket の詳細表示 / 関連文書検索 / 回答案生成 |

---

## 1. 起動直後の状態確認

ブラウザで `http://127.0.0.1:8000` を開くと以下が確認できます。

- **トップバー右上のバッジ** — 現在の LLM プロバイダーを示します
  - `Provider: mock`（黄色背景）: Mock モード（API Key 不要）
  - `Provider: watsonx`（青色背景）: IBM watsonx.ai 接続中
- **左ペインのチケット一覧** — 初期データが20件ずつ表示されます
- **右ペイン** — 「左の一覧からチケットを選択してください」と表示されます（チケット未選択状態）

---

## 2. チケット一覧の操作

### 2.1 一覧の見方

左ペインの各行は1つのチケットを表します。

```
TKT-00000001          ← チケットID（グレー・細字）
パスワードを忘れた    ← タイトル（黒・太字）
完了                  ← ステータス（グレー・細字）
```

- 選択中のチケットは **左に青いボーダー + 薄青背景** でハイライトされます

### 2.2 ステータスで絞り込む

1. 左ペイン上部の入力欄に絞り込みたいステータスを入力します  
   例: `対応中`、`完了`、`様子見`
2. **「絞り込み」ボタン** をクリック（または `Enter` キー）
3. 一覧が入力したステータスのみに更新されます
4. 絞り込みを解除するには入力欄を空にして「絞り込み」をクリックします

> **Note**: ステータス値は完全一致ではなく部分一致で動作します

### 2.3 さらに読み込む（ページング）

初期表示は20件です。一覧下部の **「さらに読み込む」ボタン** が有効になっている場合、クリックすることで次の20件が追加表示されます。ボタンがグレーアウトしている場合はすべて読み込み済みです。

---

## 3. チケット詳細の確認

左ペインでチケットをクリックすると右ペインに詳細が表示されます。

```
Q1020-01  [対応中]            ← 受付番号 / ステータスバッジ
3人掛けソファ「モリ」: 配送予定日… ← タイトル
お客様: … | 商品: … | カテゴリ: 未判定 | 緊急度: 未判定

┌─────────────────────────────┐
│ 配送予定日（10/22）を10/25に │  ← 問い合わせ内容（description）
│ 変更したい                   │
└─────────────────────────────┘

[🔍 関連文書を検索]  [✏️ 回答案を作成]
```

| 項目 | 説明 |
|---|---|
| 受付番号 | `Q1020-01`（取込データ）または`TKT-XXXXXXXX`（フォーム送信）。Backendが発行 |
| ステータスバッジ | `未対応` / `対応中` / `完了` |
| タイトル | 商品名と問い合わせ内容の先頭部分から自動生成 |
| お客様・商品・カテゴリ・緊急度 | 表示のみ。氏名は検索・回答案生成に使用されません |
| 問い合わせ内容 | 検索と回答案生成に使用される文章 |

> 回答案には「分類案」（カテゴリ・緊急度・対応区分・担当・FAQ番号）が表示されることがあります。確定値ではないため、必ず担当者が確認してください。

### 新規問い合わせの登録

画面右上の「＋ 新規問い合わせ」から、問い合わせフォームを開きます。必須項目は「お名前」「メールアドレス」「お問い合わせの種類」「お問い合わせ内容」です。写真は添付の有無だけを記録し、画像本体は保存されません。送信後に受付番号が表示されます。

## 4. 関連文書の検索（ナレッジ検索）

チケットを選択した状態で **「🔍 関連文書を検索」ボタン** をクリックします。

### 動作の流れ

1. 選択中チケットのタイトル + 説明文を組み合わせたクエリを自動生成
2. ベクトルインデックス（`data/index/`）に対してコサイン類似度検索を実行
3. 上位5件の関連文書チャンクを表示

### 検索結果の見方

```
検索結果
─────────────────────────────────────────────
[1] VPN接続トラブルシューティング             ← タイトル
VPNクライアントを最新版に更新してください…    ← スニペット（本文抜粋）
vpn_troubleshooting / score: 0.987            ← ソース名 / 類似度スコア
─────────────────────────────────────────────
[2] FAQ: VPNに接続できません
セルフサービスポータルにアクセスして…
FAQ / score: 0.941
```

| 表示要素 | 説明 |
|---|---|
| `[n]` 番号 | 検索順位（1が最も関連度が高い） |
| タイトル | 文書・チャンクのタイトル |
| スニペット | 文書の該当箇所の抜粋 |
| ソース名 | 文書ファイル名またはカテゴリ |
| score | コサイン類似度（通常-1〜1、高いほど関連度が高い）。正答確率ではない |

> **Mock モードの注意**: Mock Embedding を使用している場合、スコアはランダムシードに基づく擬似値です。実際の意味的類似度ではありません

---

## 5. 回答案の生成（RAG + LLM）

チケットを選択した状態で **「✏️ 回答案を作成」ボタン** をクリックします。

### 動作の流れ

1. 選択中チケットのタイトル + 説明文でナレッジ検索（上位5件）
2. 検索結果を文脈として LLM にプロンプトを送信
3. 生成された回答下書きを表示

### 回答案エリアの見方

```
回答案  (Human Review が必要です)
─────────────────────────────────
⚠️ この回答は AI が生成した下書きです。必ず内容を確認してから
   使用してください。自動送信はされません。
─────────────────────────────────
┌─────────────────────────────────┐
│ お問い合わせありがとうございます。│  ← 回答テキスト（編集可能）
│ パスワードのリセット手順は…      │
└─────────────────────────────────┘

参照元
─────────────────────────────────
[FAQ001] FAQ: パスワードを忘れた          ← 参照元文書1
セルフサービスポータルにアクセスし…
FAQ / score: 0.995

[DOC001] account_troubleshooting.pdf     ← 参照元文書2
…

Provider: mock | Model: mock-llm-v1 | Request ID: xxxx-xxxx  ← メタ情報
```

| 表示要素 | 説明 |
|---|---|
| 回答テキスト | AI が生成した回答下書き（テキストエリアで編集可能） |
| 警告ボックス | 自動送信されない旨の注意文（常時表示） |
| 参照元 | 回答生成に使用した文書（`citation_id` / タイトル / スニペット） |
| Provider / Model | 使用した LLM プロバイダーとモデル名 |
| Request ID | API リクエストのトレース用 ID |

> **重要**: 回答テキストは **編集可能**です。必ず内容を確認・修正してから実際のユーザーへの返信に使用してください

---

## 6. 「処理中…」表示について

「🔍 関連文書を検索」または「✏️ 回答案を作成」ボタンをクリックすると、API 応答待ちの間 **「処理中…」** テキストが表示されます。応答が返ると自動で消えます。

---

## 7. エラー表示

操作中にエラーが発生した場合、右ペイン下部に赤いエラーボックスが表示されます。

```
エラー: チケット一覧の取得に失敗しました: HTTP 503
```

| よくあるエラー | 原因 | 対処 |
|---|---|---|
| `HTTP 503` | RAG インデックスが未構築 | `make index` を実行してサーバーを再起動 |
| `チケットが見つかりません` | 絞り込み結果が0件 | 入力値を確認、または絞り込みをクリア |
| `回答案の生成に失敗しました` | LLM エラーまたは接続失敗 | `.env` の設定を確認、Mock モードで再試行 |

次の操作を行うと自動でエラーボックスは消えます。

## 9. API を直接使う場合（上級者向け）

GUI が呼び出しているエンドポイントは以下のとおりです。curl や Postman からも操作できます。

| 操作 | メソッド | エンドポイント | 主なパラメータ |
|---|---|---|---|
| チケット一覧取得 | `GET` | `/api/v1/tickets` | `status`, `limit`, `cursor` |
| チケット詳細取得 | `GET` | `/api/v1/tickets/{ticket_id}` | — |
| チケット作成 | `POST` | `/api/v1/tickets` | `customer_name`, `customer_email`, `inquiry_type`, `description`（任意: `order_number`, `product_name`, `has_attachment`） |
| チケット更新 | `PATCH` | `/api/v1/tickets/{ticket_id}` | 変更したいフィールドのみ |
| ナレッジ検索 | `POST` | `/api/v1/search` | `query`, `top_k` |
| 回答案生成 | `POST` | `/api/v1/answers/draft` | `ticket_id` または `question`, `top_k` |
| LLM 直接生成 | `POST` | `/api/v1/llm/generate` | `prompt` |
| ヘルスチェック | `GET` | `/api/v1/health/live` | — |

インタラクティブな API ドキュメント（Swagger UI）は起動中サーバーの `/docs` で確認できます:

```
http://127.0.0.1:8000/docs
```
