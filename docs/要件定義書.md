# ヘルプデスクRAG共通基盤 要件定義書

## 1. 目的

学生がヘルプデスク支援アプリケーションを短期間で開発できる共通基盤を提供する。標準構成はMac／Windows上でFastAPIを実行し、生成LLMとEmbeddingにはWatson Machine Learning（watsonx.ai Runtime）が提供するwatsonx.ai API、Vector DBにはIBM watsonx.data Milvusを使用する。watsonx.ai StudioはProject管理、Cloud Object StorageはProject関連ストレージとして使用する。IBM Cloudへのアプリケーション配備は必須とせず、Docker／Podmanも任意とする。

### 1.1 利用期間

- 利用開始: 2026年10月10日
- 利用終了: 2026年12月31日
- 最大期間: 83暦日、1,992時間
- 終了時にAPI Keyの失効と不要なIBM Cloud resourceの停止・削除を確認する。

### 1.2 利用規模とリージョン

- 利用者: 8名
- グループ構成: 4名×2グループ
- IBM Cloudリージョン: 東京（`jp-tok`）
- IBM Cloud環境は2グループで共有する。Project、Milvus database、collectionをグループ別に分離する場合は申請前に追加数量を確定する。

### 1.3 実装仕様の前提

| 項目 | 採用仕様 | 位置付け |
|---|---|---|
| 実装言語 | Python 3.14、HTML5 | PythonはBackend、HTMLはFrontendに使用する。CSSとブラウザ標準JavaScriptは画面表示・API呼び出しの補助に限定する |
| Webフレームワーク | FastAPI | API、入力検証、OpenAPI生成、静的HTML配信を担当する |
| LLMサービス | Watson Machine Learning（watsonx.ai Runtime） | 標準実行環境で必須。watsonx.aiの生成モデルとEmbeddingモデルをAPI利用する |
| Project管理 | watsonx.ai Studio | `WATSONX_PROJECT_ID`で使用するProjectを作成・管理する |
| Project関連ストレージ | Cloud Object Storage | watsonx.ai Projectに関連付ける。既存instanceを再利用できる場合も申請対象として明記する |
| Vector DB | IBM Cloud上のwatsonx.data Milvus | 標準実行環境で必須。Compose内には構築しない |
| アプリ実行環境 | 学生のMac／Windows | Python直接実行を標準とする |
| コンテナ | Docker／Podman Compose | 任意。利用できる場合の代替実行方法 |

Mock LLMとNumPy Vector Storeは単体テスト、CI、IBM Cloud障害時の学習継続だけに使用する代替実装であり、標準構成の採用サービスではない。

## 2. 利用者

| 利用者 | 主な責務 |
|---|---|
| 運営担当 | IBM Cloud環境、Milvus collection、資格情報、配布ZIPを準備する |
| 学生 | 共通APIを利用または拡張してヘルプデスク支援アプリを開発する |
| レビュー担当 | 機能、安全性、根拠表示、Human Review、評価結果を確認する |

## 3. スコープ

### 3.1 対象

- Mac／WindowsでのPython直接実行
- 任意のDockerまたはPodmanによるアプリケーション起動
- Mock Ticket APIとMaster API
- watsonx.aiによる回答下書き生成
- watsonx.aiによる文書・質問のEmbedding
- watsonx.data Milvusによる類似文書検索
- 根拠文書付き回答下書き
- 静的Frontend
- テスト・学習継続用Mock／NumPy代替構成

### 3.2 対象外

- IBM Cloudリソースの自動作成
- IBM Cloudへのアプリケーション配備
- 独自機械学習モデルの学習、チューニング、デプロイ
- Foundation Modelの専有環境へのDeploy on Demand
- 学習用GPU、Notebook runtime、deployment space
- 本番IAM／SSOの実装
- 回答の自動送信
- Milvus collectionの自動削除
- 高可用性、複数リージョン、災害対策
- 実個人情報や実顧客情報の利用

## 4. 機能要件

| ID | 要件 | 優先度 | 受入条件 |
|---|---|---:|---|
| FR-01 | Ticket一覧・詳細を取得できる | Must | 既定20件でpaginationできる |
| FR-02 | 架空Ticketを作成・更新できる | Must | validationとversion競合を処理する |
| FR-03 | 問い合わせから関連文書を検索できる | Must | Milvusからsourceとscore付きで返る |
| FR-04 | 回答下書きを生成できる | Must | watsonx.aiを呼び出し、Human Review必須で返る |
| FR-05 | 回答に根拠文書を付ける | Must | LLMが生成したsourceを信用せず、検索metadataから付加する |
| FR-06 | 根拠不足時に回答を控える | Must | 閾値以上が0件ならLLMを呼ばない |
| FR-07 | Providerを設定で切り替えられる | Should | 標準のwatsonx.ai／Milvusから、テスト用Mock／NumPyへコード変更なしで切り替えられる |
| FR-08 | Browserから最小UIを利用できる | Must | Ticket、検索、回答、引用を1画面で確認できる |
| FR-09 | Health checkを提供する | Must | livenessとreadinessを分離する |
| FR-10 | 文書アクセス範囲を検索前に適用する | Must | Milvus検索条件に`access_scope`と`is_active`を含め、許可外文書を検索候補へ入れない |
| FR-11 | 引用元Chunkを追跡できる | Must | Citationにserver-sideで確定した`chunk_id`と検索scoreを含める |

## 5. 外部サービス要件

### 5.1 watsonx.ai

- `watsonx.ai Runtime`はIBM提供の生成LLM／Embedding APIを利用するためのservice instanceおよび課金基盤として使用する。
- 独自の機械学習モデルやFoundation Modelを作成・デプロイしない。
- Project ID、API Key、リージョンURLを運営側が用意する。
- `WATSONX_URL`は東京リージョンの`https://jp-tok.ml.cloud.ibm.com`を使用する。
- 生成Model IDとEmbedding Model IDを環境変数で設定する。
- 生成ModelとEmbedding Modelが東京リージョンで利用可能であることを申請時と授業開始前に確認する。
- Model IDをソースコードへ固定しない。
- 生成とEmbeddingで同一API Keyを利用する場合も、Frontendへ公開しない。
- 8名で1つの資格情報を共有せず、サービス側の認証仕様が許す範囲でグループ単位の資格情報2組に分離する。
- 利用量、rate limit、timeoutを運営側で管理する。

### 5.2 watsonx.data Milvus

- IBM Cloud上でMilvus serviceとdatabase、collectionを運営側が作成する。
- watsonx.dataとMilvusは東京リージョン（`jp-tok`）を使用する。
- 接続にはTLSを使用する。
- API Key認証では、`MILVUS_USERNAME`に`ibmlhapikey_<watsonx.data username>`、`MILVUS_PASSWORD`にwatsonx.dataをプロビジョニングしたIBM Cloudアカウントで発行したIBM Cloud API Keyを設定する。
- IAM access token認証では、`MILVUS_USERNAME`に`ibmlhtoken_<watsonx.data username>`、`MILVUS_PASSWORD`にIAM access tokenを設定する。旧形式の`ibmlhapikey`／`ibmlhtoken`単独指定は使用しない。
- IBM Cloud画面で取得したgRPC host／portから`MILVUS_URI`を構成し、接続形式は事前検証したPyMilvusの形式へ統一する。MVPでは`MILVUS_HOST`／`MILVUS_PORT`を併設せず、設定の優先順位を曖昧にしない。
- collectionのVector次元はwatsonx.ai Embedding modelの出力次元と一致させる。
- collectionには`chunk_id`、`document_id`、`title`、`text`、`source`、`document_type`、`category`、`access_scope`、`is_active`、`updated_at`、`content_hash`、`vector`を保持する。
- 検索時は`access_scope`と`is_active=true`をMilvus filterへ必ず含める。検索後の除外だけに依存しない。
- 文書更新はupsert、削除は`document_id`単位でVectorも削除する。
- Embedding model、dimension、metric、Chunk schema versionをcollection contractとして管理し、アプリ設定と一致しない場合はreadinessを503にする。

## 6. 実行環境要件

| ID | 要件 |
|---|---|
| ER-01 | ZIP展開後、Mac／WindowsでPython直接実行できる |
| ER-02 | アプリケーションは`127.0.0.1`へbindし、LANやInternetへ公開しない |
| ER-03 | watsonx.aiとMilvusへのOutbound TLS通信を許可する |
| ER-04 | `.env`、API Key、passwordをGit、配布ZIP、提出物へ含めない |
| ER-05 | 現行実装はPython 3.12、移行完了後の目標はPython 3.14と明示する |
| ER-06 | BrowserへIBM Cloud資格情報を渡さず、Backend processだけが環境変数から取得する |
| ER-07 | watsonx.ai RuntimeとMilvusはIAM／Access Policyおよびresource権限をサービス側で検証する |
| ER-08 | Docker／PodmanはFastAPIの実行方式として扱い、独立した業務コンポーネントや必須環境にしない |

### 6.1 任意のコンテナ要件

| ID | 要件 |
|---|---|
| CR-01 | コンテナを選択した場合、同一`compose.yaml`をDocker ComposeとPodman Composeで使用できる |
| CR-02 | アプリは非root userで実行する |
| CR-03 | root filesystemはread-onlyとし、runtime volumeと`/tmp`だけを書き込み可能にする |
| CR-04 | API Keyやpasswordをimage layerへ含めない |
| CR-05 | Host公開は既定で`127.0.0.1`に限定する |
| CR-06 | liveness/readiness healthcheckを設定する |
| CR-07 | `.dockerignore`で評価データ、runtime、cache、`.env`をbuild contextから除外する |
| CR-08 | ImageはPython 3.14系へ固定し、Python 3.14で再生成した`uv.lock`から依存を再現する |

## 7. 非機能要件

| 観点 | 要件 |
|---|---|
| セキュリティ | 秘密情報非表示、TLS、入力検証、Prompt Injection対策、Human Review |
| 可用性 | 外部サービス障害時はRAG APIで503を返し、誤った空回答を成功扱いしない |
| 性能 | 教材の標準データ量・単一worker・通常ネットワークで、Ticket API P95 500ms以内、Vector検索P95 3秒以内、生成はtimeout以内を目標値とする |
| 拡張性 | LLM、Embedding、Vector StoreをPort／Adapterで分離する |
| 観測性 | request ID、provider、model、検索件数、処理時間、結果を記録する |
| プライバシー | Ticket本文、Prompt、生成全文、Credentialを標準ログへ出さない |
| 再現性 | ZIP展開後、Mac／Windows向け手順で起動可能にする。Composeは任意とする |

## 8. データ保持要件

- Python直接実行ではTicket runtimeを`data/runtime`へ保存する。コンテナ実行時だけnamed volumeを使用する。
- VectorはIBM Cloud Milvusを正本とし、コンテナ内へ永続化しない。
- LLM入出力は既定で保存しない。
- 文書削除時はMilvus、cache、配布データへの残存を確認する。
- ZIPへ`.env`、更新済みruntime、実Keyを含めない。

## 9. 前提条件

- 実装言語はPython 3.14とHTML5、WebフレームワークはFastAPIとする。
- 標準実行時のLLMおよびEmbeddingサービスはwatsonx.aiとする。
- 標準実行時のVector DBはIBM Cloud上のwatsonx.data Milvusとする。
- 学生のMac／Windowsからwatsonx.aiとwatsonx.data MilvusへOutbound接続できるネットワークである。
- Milvus collectionへの権限が付与されている。
- collectionはアプリ起動前に作成・投入済みである。
- watsonx.data Milvus server versionを確認し、対応するPyMilvus major／minorを固定している。
- Python 3.14対応の`ibm-watsonx-ai>=1.7.2,<2`を使用し、yankedではない検証済み版をlockしている。
- JSON Ticket Repositoryを使用するMVPはUvicorn workerを1に固定する。
- Python直接実行では`uv`を利用できる。コンテナ実行を選択する場合だけDocker ComposeまたはPodman Composeを利用できる。
- `sample_asset` repository内にSeed再生成用Excelを同梱するため、その正解ラベルは学生から閲覧可能である。

## 10. 受入試験

1. MacとWindowsの手順でMockモードを起動できる。
2. IBM Cloudへアプリを配備せず、ローカルFastAPIからwatsonx.aiとMilvusへ接続できる。
3. `/health/live`が200を返す。
4. watsonx.aiの必須設定が存在し、Milvusへ認証・接続でき、database、collection、必須field、Vector次元、collection contractが一致する場合、`/health/ready`が200を返す。
5. VPNの問い合わせでVPN関連文書が検索される。
6. 回答下書きに検索済みsourceが付く。
7. 無効なMilvus資格情報でreadinessが503になる。
8. Python process再起動後もruntime Ticketが`data/runtime`に残る。コンテナ選択時はvolumeに残る。
9. FrontendがHTMLとしてFastAPIから配信され、Node.jsなしで利用できる。
10. Backendの実行環境がPython 3.14系で、APIがFastAPIのOpenAPI定義と一致する。
11. 許可外`access_scope`または`is_active=false`の文書が検索結果へ入らない。
12. Citationの`chunk_id`が同一リクエストのMilvus検索結果に存在し、scoreとmetadataがserver-side値に一致する。
13. `DraftAnswerRequest`は`ticket_id`と`question`のどちらか一方だけを受理し、両方指定または両方未指定を422にする。
14. コンテナを使用しなくても受入試験を完了できる。
15. 申請数量と予算を`docs/IBM_Cloud申請見積.md`の式で算定できる。

## 11. Python 3.14移行に関する注記

- 本書の目標実行環境はPython 3.14とする。
- 現行実装の`pyproject.toml`、`uv.lock`、`Dockerfile`、mypy設定は別作業でPython 3.14へ移行する。
- 移行時はwatsonx.ai SDK、PyMilvus、FastAPIを含む全依存をPython 3.14上で再解決する。
- `ibm-watsonx-ai`は`>=1.7.2,<2`を最低条件とし、PyMilvusは接続先Milvus serverと同じmajor／minor系列に制限する。
- lock時はyanked releaseを採用せず、解決した版を授業前に固定する。
- 全テスト、lint、型検査、Docker／Podmanのimage buildと起動確認が完了するまで、Python 3.14対応完了とは判定しない。

## 12. 後続実装で反映する設計差分

本改訂は設計とAPI契約を先行更新している。次は未実装として管理し、実装・全テストを行う後続作業で同時に反映する。コンテナbuildは任意実行方式の確認として扱う。

- Python 3.14へのruntime、依存lock、mypy、Dockerfileの移行
- Citationの`chunk_id`／`score`追加とOpenAPI contract test更新
- Milvus schema、検索前scope filter、collection contract検証
- 実行モード別readinessとprovider errorの503変換
- 明示的なingestion管理command
- 接続先Milvus serverに合わせたPyMilvus version固定

これらが完了するまで、設計準拠完了とは判定しない。

## 13. IBM Cloud申請対象

- 必須申請サービス: Watson Machine Learning（watsonx.ai Runtime）、watsonx.ai Studio、Cloud Object Storage、watsonx.data／Milvus
- Watson Machine Learning（watsonx.ai Runtime）では、IBM提供済みの生成LLM／Embedding APIだけを利用し、独自モデルの学習・デプロイ用CUHは0とする。
- watsonx.ai StudioではProjectを1つ作成・管理し、Studio上のNotebookや計算環境を使用しない場合のCUHは0とする。
- Cloud Object Storageはwatsonx.ai Projectの関連ストレージとして使用する。保存量とrequest数は実利用見込みを入力する。
- watsonx.data内にMilvusサービス、database、collectionを作成する。アカウント制約により見積へ追加できない場合は未申請・未計上として明記し、利用開始前に追加する。
- サービス申請不要の共通基盤設定: IBM Cloud IAMのService ID、API Key、Access Policy、およびProject ID、生成Model ID、Embedding Model ID。IAM設定自体は環境準備作業として依頼する。
- 任意: IBM Cloud上のアプリ実行環境、Container Registry、Cloud側のsecret manager
- 利用量と費用は[IBM Cloud申請・利用見積](./IBM_Cloud申請見積.md)で算定する。
- Mac／Windowsの導入手順は[環境構築手順](./環境構築手順_Mac_Windows.md)を正本とする。
