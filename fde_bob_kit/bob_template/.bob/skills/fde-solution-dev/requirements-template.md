## 3. 機能要件

| 要件 ID | 要件（〜できる） | 課題 ID | 担い手 | 優先度 | 受け入れ基準（観測できる形） | 必要リソース（02 の ID） |
|---|---|---|---|---|---|---|
| FR-001 | | P-01 | AI / 人 / システム | Must / Should / Could | | R-xx |

書き方のルール:

- 1 要件 1 文。「〜できる」で終える。
- 受け入れ基準は数・時間・有無など確認できる形にする（例: 評価チケット 20 件のうち、根拠付きで提案できた割合）。
- 担い手が「AI」の要件には、対になる「人が確認・修正する」要件を置く。
- Must は MVP だけにする。迷ったら Should に下げる。

## 4. 非機能要件

| 要件 ID | 観点 | 要件 |
|---|---|---|
| NFR-001 | セキュリティ・プライバシー | 個人情報・機密を LLM・ログ・Git に渡さない |
| NFR-002 | 責任ある AI | AI の出力は自動送信・自動確定せず、人が確認する |
| NFR-003 | 説明可能性 | 判断や回答には根拠（参照元）を表示する |
| NFR-004 | 運用 | 参照文書や基準の更新担当と更新手順が決まっている |
| NFR-005 | 性能 | （例: 1 件の提案を ○ 秒以内に返す） |
