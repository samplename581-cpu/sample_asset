# Gmail問い合わせ管理自動化システム 作成・運用手順書

## 1. システムの概要

### 1.1 目的

問い合わせ窓口の担当者が、メールに記載されたお客様情報や問い合わせ内容を手作業でスプレッドシートに転記している業務を自動化する。

これにより、以下の効果を期待する。

- 問い合わせ内容の転記作業の削減
- 入力ミスや転記漏れの防止
- 問い合わせ対応の迅速化
- 添付画像の一元管理
- 問い合わせ対応状況の可視化

### 1.2 使用するサービス

| サービス | 用途 |
|---|---|
| Gmail | 問い合わせメールの受信 |
| Googleスプレッドシート | 問い合わせ情報の管理 |
| Google Drive | 添付画像の保存 |
| Google Apps Script（GAS） | メール取得、本文解析、自動登録 |
| 時間主導型トリガー | プログラムの定期実行 |

外部APIや生成AIを使用せず、Googleのサービスのみで構築する。通常のGoogleアカウントで作成可能である。ただし、各サービスの利用上限や組織の管理者設定に従う必要がある。

### 1.3 システムの処理の流れ

1. お客様が問い合わせフォームから問い合わせを送信する。
2. 問い合わせ窓口のGmailにメールが届く。
3. GASが5分ごとに対象メールを検索する。
4. メールの本文から受付番号、お客様名、問い合わせ内容などを抽出する。
5. 登録済みのメールIDと受付番号を確認する。
6. 添付されているJPG画像をGoogle Driveに保存する。
7. 抽出した情報と画像のリンクをスプレッドシートに登録する。
8. 担当者が問い合わせ内容を確認し、カテゴリ、緊急度、対応区分などを入力する。
9. 担当者が問い合わせへの回答や専門部署への引き継ぎを行う。

処理中にエラーが発生した場合は、エラーログ用のシートに記録する。

## 2. システムの仕様

### 2.1 管理表の列構成

| 列 | 項目 | 入力方法 |
|---|---|---|
| A | 受付番号 | 自動入力 |
| B | 受付日時 | 自動入力 |
| C | お客様名 | 自動入力 |
| D | メールアドレス | 自動入力 |
| E | 注文番号 | 自動入力 |
| F | 商品名 | 自動入力 |
| G | 問い合わせ内容（要約） | 自動入力 |
| H | カテゴリ | 手入力・プルダウン |
| I | 緊急度 | 手入力・プルダウン |
| J | 対応区分 | 手入力・プルダウン |
| K | 担当 | 手入力・プルダウン |
| L | ステータス | 初期値は未対応・プルダウン |
| M | FAQ番号 | 手入力 |
| N | 備考 | 手入力 |
| O | 添付画像 | 自動入力・画像リンク |
| P | メールID | 自動入力・非表示 |

A～G列およびO～P列はプログラムが自動入力する。

H～N列は担当者が入力する。ただし、L列のステータスについては、新規登録時に「未対応」を自動入力する。

メール本文に「お問い合わせの種類」が記載されていても、カテゴリには自動入力しない。

また、問い合わせ内容（要約）には、メールに記載された問い合わせ内容をそのまま登録する。現時点ではAIによる要約は行わない。

### 2.2 実装機能

| 機能 | 内容 |
|---|---|
| メール自動取得 | Gmailから対象メールを取得する |
| 自動転記 | メール本文から必要な情報を抽出する |
| 定期実行 | 5分ごとに自動実行する |
| 手動実行 | 任意のタイミングでメールを取得する |
| 画像保存 | JPG・JPEG画像をGoogle Driveに保存する |
| 画像リンク | 管理表から保存された画像を開く |
| 重複防止 | メールIDと受付番号で重複を判定する |
| 空欄対応 | 注文番号などが空欄でも登録する |
| 複数行対応 | 問い合わせ内容の改行を保持する |
| ソート | 受付日時の新しい順・古い順に並べ替える |
| フィルタ | 特定の条件で問い合わせを絞り込む |
| プルダウン | 手入力項目の表記揺れを防止する |
| 色分け | 緊急度やステータスに応じて色を変更する |
| エラー記録 | 処理に失敗したメールの情報を記録する |
| 既存データ保護 | 登録済みの担当者入力内容を上書きしない |

### 2.3 プルダウンの選択肢

**カテゴリ**

- 配送関連
- 商品不良・破損
- 組み立て・使い方
- 店舗・在庫・その他
- 注文変更・キャンセル

**緊急度**

- 高
- 中
- 低

**対応区分**

- FAQで回答
- 専門部署へ引き継ぎ

**担当**

- 窓口担当
- 配送センター担当
- 修理・アフターサービス担当

**ステータス**

- 未対応
- 対応中
- 完了

### 2.4 色分け

| 項目 | 値 | 背景色 |
|---|---|---|
| 緊急度 | 高 | 赤 |
| 緊急度 | 中 | 黄色 |
| 緊急度 | 低 | 緑 |
| ステータス | 未対応 | 赤 |
| ステータス | 対応中 | 黄色 |
| ステータス | 完了 | 緑 |

## 4. Google Driveの設定

### STEP 1：Google Driveを開く

以下のURLにアクセスする。

https://drive.google.com/drive/my-drive

Googleアカウントにログインする。

### STEP 2：画像保存用フォルダを作成する

1. Google Driveの画面左上にある「＋ 新規」をクリックする。
2. 「新しいフォルダ」をクリックする。
3. フォルダ名に「問い合わせ添付画像」と入力する。
4. 「作成」をクリックする。

このフォルダに問い合わせメールの添付画像が保存される。

### STEP 3：フォルダIDを取得する

1. 作成した「問い合わせ添付画像」フォルダをダブルクリックする。
2. ブラウザ上部のアドレスバーを確認する。

URLは以下のような形式になっている。

https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz

「folders/」より後ろの文字列がフォルダIDとなる。

上記の場合、フォルダIDは以下の部分である。

1AbCdEfGhIjKlMnOpQrStUvWxYz

URLに「?」が含まれる場合は、それ以降を除く。

実際に作成したフォルダのIDをコピーし、メモ帳などに保存する。

このIDは後ほどGASの設定で使用する。

---

## 5. Googleスプレッドシートの作成

### STEP 4：スプレッドシートを新規作成する

以下のURLにアクセスする。

https://sheets.google.com/

1. 「空白のスプレッドシート」をクリックする。
2. 画面左上の「無題のスプレッドシート」をクリックする。
3. ファイル名を「問い合わせ管理システム」に変更する。

この時点では、セルに項目名やデータを入力する必要はない。

管理表の項目名、列幅、色分け、プルダウンなどはプログラムによって自動設定される。

## 6. Google Apps Scriptの設定

### STEP 5：Apps Scriptを開く

1. 作成したスプレッドシートを開く。
2. 画面上部の「拡張機能」をクリックする。
3. 「Apps Script」をクリックする。
4. 新しいタブでApps Scriptの編集画面が開く。

### STEP 6：プロジェクト名を変更する

1. Apps Script画面左上の「無題のプロジェクト」をクリックする。
2. プロジェクト名を「問い合わせ管理自動化」に変更する。

### STEP 7：初期コードを削除する

画面左側に「コード.gs」というファイルがある。

初期状態では、以下のコードが入力されている。

function myFunction() {

}

コード編集欄をクリックし、Ctrl + Aでコードをすべて選択する。

BackspaceまたはDeleteキーを押して削除する。

### STEP 8：プログラムを貼り付ける

1. 別添の「gmail_inquiry_apps_script.txt」を開く。
2. Ctrl + Aでプログラムをすべて選択する。
3. Ctrl + Cでコピーする。
4. Apps Scriptのコード編集欄をクリックする。
5. Ctrl + Vでプログラムを貼り付ける。

一部分だけではなく、必ずプログラム全体をコピーすること。

以前のコードが存在する場合は、既存のコードをすべて削除してから貼り付ける。

---

## 7. プログラムの基本設定

### STEP 9：フォルダIDを設定する

コードの先頭付近にCONFIGという設定項目がある。

初期状態では以下のようになっている。

```javascript
const CONFIG = {
  SHEET_NAME: '問い合わせ管理',
  ERROR_SHEET_NAME: 'エラーログ',
  FOLDER_ID: 'ここにフォルダIDを入力',
  GMAIL_QUERY: 'subject:"お問い合わせ" newer_than:30d -in:trash -in:spam',
  SUBJECT_PREFIX: '【お問い合わせ】',
  SENDER_EMAIL: '',
  INTERVAL: 5,
  AUTO_SORT: true,
  TIMEZONE: 'Asia/Tokyo'
};
```

FOLDER_IDの部分を、STEP 3で取得したフォルダIDに変更する。

変更前：

```javascript
FOLDER_ID: 'ここにフォルダIDを入力',
```

変更後の例：

```javascript
FOLDER_ID: '1AbCdEfGhIjKlMnOpQrStUvWxYz',
```

実際に取得したフォルダIDを入力すること。

文字列を囲む引用符と、末尾のカンマは削除しない。

### STEP 10：その他の設定を確認する

| 設定項目 | 内容 |
|---|---|
| SHEET_NAME | 問い合わせ管理表のシート名 |
| ERROR_SHEET_NAME | エラーログのシート名 |
| FOLDER_ID | 添付画像の保存先フォルダID |
| GMAIL_QUERY | Gmailの検索条件 |
| SUBJECT_PREFIX | 対象メールの件名の先頭文字列 |
| SENDER_EMAIL | 対象メールの送信元アドレス |
| INTERVAL | 自動実行間隔（分） |
| AUTO_SORT | 新規登録時の自動ソートの有無 |
| TIMEZONE | 使用するタイムゾーン |

テスト段階ではFOLDER_ID以外を変更する必要はない。

### 7.1 自動実行間隔を変更する場合

初期状態では5分ごとに実行される。

```javascript
INTERVAL: 5,
```

1分ごとに実行したい場合は以下に変更する。

```javascript
INTERVAL: 1,
```

設定可能な実行間隔は1、5、10、15、30分である。

デモンストレーションでは1分、通常運用では5分を目安とする。

設定変更後は、コードを保存してsetupTriggerを再実行する必要がある。

### 7.2 特定の送信元だけを対象にする場合

初期状態では、送信元メールアドレスを指定していない。

```javascript
SENDER_EMAIL: '',
```

実際の企業で運用する場合は、問い合わせフォームの送信元アドレスを指定する。

設定例：

```javascript
SENDER_EMAIL: 'form-noreply@company.example',
```

上記のアドレスは仮想企業のものであるため、実際の運用時には実在する送信元アドレスを指定する。

自分自身にテストメールを送信する場合は空欄にしておく。

### 7.3 自動ソートを無効にする場合

初期状態では、新規メールが登録されると受付日時の新しい順に並べ替えられる。

```javascript
AUTO_SORT: true,
```

自動ソートを無効にする場合は以下に変更する。

```javascript
AUTO_SORT: false,
```

複数人が同時に管理表を編集する場合は、作業中に行が移動することを防ぐため、自動ソートを無効にすることも検討する。

### STEP 11：コードを保存する

画面上部の保存ボタンをクリックする。

または、Ctrl + Sを押して保存する。

今回のシステムではWebアプリとして公開する必要がないため、「デプロイ」ボタンを押す必要はない。

## 8. 初期設定の実行

### STEP 12：実行する関数を選択する

Apps Script画面上部に、実行する関数を選択するプルダウンがある。

プルダウンをクリックし、以下の関数を選択する。

setupTrigger

この関数は、管理表の初期設定と自動実行の設定を行う。

### STEP 13：初期設定を実行する

setupTriggerを選択した状態で、画面上部の「実行」をクリックする。

初回実行時にはGoogleアカウントへのアクセス権限の確認画面が表示される。

### STEP 14：アクセス権限を許可する

1. 「権限を確認」をクリックする。
2. 使用するGoogleアカウントを選択する。
3. 要求されているアクセス権限を確認する。
4. 自分で作成したプログラムであることを確認し、必要な権限を許可する。

「Googleで確認されていないアプリ」という警告が表示される場合がある。

自分で作成したプロジェクトであり、コードの内容を確認できている場合に限り、「詳細」からプロジェクトへの移動を選択し、権限の確認を続ける。

必要となる主な権限は以下のとおり。

| 権限 | 使用目的 |
|---|---|
| Gmail | 問い合わせメールの取得 |
| Google Drive | 添付画像の保存 |
| Googleスプレッドシート | 問い合わせ情報の登録 |
| Apps Script | 自動実行トリガーの作成 |

組織のGoogleアカウントでは、管理者によって権限が制限されている場合がある。

### STEP 15：実行結果を確認する

Apps Script画面下部の実行ログを確認する。

正常に実行された場合は、以下のような内容が表示される。

実行開始

初期設定完了

実行完了

赤色のエラーが表示された場合は、後述するエラー対処方法を確認する。

### STEP 16：スプレッドシートを確認する

1. スプレッドシートのタブに戻る。
2. F5キーを押して画面を再読み込みする。
3. 画面下部のシート一覧を確認する。

以下の2つのシートが作成されていれば正常である。

- 問い合わせ管理
- エラーログ

問い合わせ管理シートには、受付番号から添付画像までの項目が作成される。

また、重複防止に使用するメールIDの列が作成されるが、通常は非表示となっている。

最初から存在している「シート1」は使用しないため、不要であれば削除してよい。

## 12. 問い合わせ管理表の使用方法

### 12.1 問い合わせ情報の確認

問い合わせ管理シートを開き、新しく登録された問い合わせを確認する。

受付番号、受付日時、お客様名、メールアドレス、注文番号、商品名、問い合わせ内容は自動入力されている。

新規問い合わせのステータスは「未対応」となっている。

### 12.2 カテゴリの入力

H列のカテゴリを選択し、プルダウンから該当する項目を選択する。

- 配送関連
- 商品不良・破損
- 組み立て・使い方
- 店舗・在庫・その他
- 注文変更・キャンセル

### 12.3 緊急度の入力

I列の緊急度を選択し、問い合わせ内容に応じて高・中・低を設定する。

判断基準の例：

| 緊急度 | 判断基準 |
|---|---|
| 高 | 安全上の問題、使用できない商品、配送直前の変更など |
| 中 | 商品の傷、注文内容の変更、交換希望など |
| 低 | 営業時間、在庫、組み立て方法などの一般的な質問 |

緊急度に応じてセルの背景色が自動的に変化する。

### 12.4 対応区分の入力

J列の対応区分から、以下のいずれかを選択する。

- FAQで回答
- 専門部署へ引き継ぎ

FAQで解決できる問い合わせについては窓口担当者が回答する。

FAQだけでは解決できない問い合わせについては、専門部署へ引き継ぐ。

### 12.5 担当者の入力

K列の担当から、対応する部署を選択する。

- 窓口担当
- 配送センター担当
- 修理・アフターサービス担当

### 12.6 ステータスの変更

L列のステータスを対応状況に応じて変更する。

| ステータス | 内容 |
|---|---|
| 未対応 | まだ問い合わせへの対応を開始していない |
| 対応中 | 窓口または専門部署が対応している |
| 完了 | 必要な対応が終了している |

### 12.7 FAQ番号と備考の入力

M列に、回答や判断に使用したFAQ番号を入力する。

N列には、担当部署への引き継ぎ事項や対応内容を入力する。

### 12.8 入力例

ベッドフレームの脚が破損している問い合わせの場合、以下のように入力する。

| 項目 | 入力内容 |
|---|---|
| カテゴリ | 商品不良・破損 |
| 緊急度 | 高 |
| 対応区分 | 専門部署へ引き継ぎ |
| 担当 | 修理・アフターサービス担当 |
| ステータス | 対応中 |
| FAQ番号 | FAQ-06 |
| 備考 | 安全上の懸念があるため使用中止を案内し、担当部署へ引き継ぐ |

なお、実際に回答や引き継ぎを行った後にステータスや備考を更新する。

## 13. 管理表の便利機能

### 13.1 手動でメールを取得する

スプレッドシートを再読み込みすると、画面上部に「問い合わせ管理」という専用メニューが表示される。

1. 「問い合わせ管理」をクリックする。
2. 「今すぐメールを取得」をクリックする。
3. 処理が完了するまで待つ。

定期実行を待たずに、新しい問い合わせメールを取得できる。

### 13.2 受付日時で並べ替える

1. スプレッドシート上部の「問い合わせ管理」をクリックする。
2. 以下のいずれかを選択する。

- 受付日時：新しい順
- 受付日時：古い順

受付日時だけでなく、お客様情報、担当者、対応状況、画像リンクなども同じ行として並べ替えられる。

### 13.3 フィルタで絞り込む

各列の見出しにあるフィルタマークをクリックすると、特定の条件に該当する問い合わせだけを表示できる。

未対応の問い合わせだけを表示する場合：

1. L列のステータスのフィルタマークをクリックする。
2. 値によるフィルタを選択する。
3. 「未対応」だけにチェックを入れる。
4. 「OK」をクリックする。

緊急度の高い問い合わせだけを表示する場合：

1. I列の緊急度のフィルタマークをクリックする。
2. 「高」だけにチェックを入れる。
3. 「OK」をクリックする。

緊急度とステータスのフィルタを組み合わせることで、優先的に対応する必要がある問い合わせを確認できる。

複数人で利用する場合は、他の担当者の表示に影響しないよう、フィルタ表示の利用も検討する。

## 14. 対象メールの形式

### 14.1 件名の形式

件名は以下の形式とする。

【お問い合わせ】受付番号 問い合わせの種類

例：

【お問い合わせ】Q1119-11 商品の傷・不具合

件名が「【お問い合わせ】」から始まらない場合は登録対象外となる。

### 14.2 本文の形式

お問い合わせフォームから、新しいお問い合わせがありました。

受付番号：

受付日時：

お名前：

メールアドレス：

注文番号：

商品名：

お問い合わせの種類：

お問い合わせ内容：

各項目は原則として1行ずつ記載する。

問い合わせ内容は複数行でも登録可能である。

### 14.3 受付日時の形式

受付日時は以下の形式で記載する。

2026/11/19 14:38

年、月、日、時、分を記載する。

管理表では「11/19 14:38」と表示されるが、内部では年を含めた日時として管理される。

### 14.4 対応するメール形式

| メールの状態 | 処理結果 |
|---|---|
| 全角コロン「：」を使用 | 正常登録 |
| 半角コロン「:」を使用 | 正常登録 |
| 注文番号が空欄 | 空欄で登録 |
| 商品名が空欄 | 空欄で登録 |
| 項目がダッシュのみ | 空欄で登録 |
| 問い合わせ内容が複数行 | 改行を保持して登録 |
| JPG画像が1枚 | 画像を保存する |
| JPG画像が複数枚 | すべての画像を保存する |
| JPEG画像が添付されている | 画像を保存する |
| 添付画像がない | 添付画像欄を空欄にする |
| PNGやPDFが添付されている | 保存対象外とする |
| 受付番号がない | エラーログに記録する |
| 受付日時が空欄 | 空欄で登録 |
| 受付日時が不正 | エラーログに記録する |
| 受付番号が重複している | 登録しない |
| 同じメールを再取得する | 登録しない |
| 件名が対象外 | 登録しない |

## 16. エラーログの確認方法

処理中にエラーが発生した場合は、エラーログシートを確認する。

### 16.1 エラーログの列構成

| 列 | 項目 | 内容 |
|---|---|---|
| A | エラー発生日時 | エラーが発生した日時 |
| B | 受付番号 | 対象の受付番号 |
| C | メール件名 | 対象メールの件名 |
| D | メールID | 対象メールの識別情報 |
| E | 処理内容 | エラーが発生した処理 |
| F | エラー詳細 | エラーの具体的な内容 |

### 16.2 エラー発生時の動作

個別のメールでエラーが発生した場合は、そのメールのエラーを記録し、他のメールの処理を継続する。

エラーが発生したメールは、検索対象期間内であれば次回の自動実行時に再処理される。

そのため、一時的なエラーであれば次回の処理で正常に登録される可能性がある。

一方、受付番号がないなどの恒久的なエラーについては、原因を解消しない限りエラーが繰り返し記録される。

## 17. エラー発生時の対処方法

### 17.1 既存シートの列構成が異なる

エラーメッセージの例：

Error: 既存シートの列構成が異なります：問い合わせ内容（要約）

**原因**

既存の問い合わせ管理シートの項目名や列の順番が、プログラムで指定している内容と一致していない。

**対処方法**

1. スプレッドシートを開く。
2. 画面下部の「問い合わせ管理」シートを右クリックする。
3. 「名前を変更」をクリックする。
4. シート名を「問い合わせ管理_旧」に変更する。
5. Apps Scriptに戻る。
6. setupTriggerを選択する。
7. 「実行」をクリックする。

新しい列構成の問い合わせ管理シートが作成される。

古いデータは「問い合わせ管理_旧」に残る。

必要に応じて、古いデータを新しい管理表へ移行する。担当者が入力した情報や受付番号の重複に注意する。

### 17.2 シートが見つからない

エラーメッセージの例：

Exception: シート「1933042743」が見つかりませんでした

**考えられる原因**

シートの削除や変更、古いシート情報の参照など。

**対処方法**

1. スプレッドシートを再読み込みする。
2. Apps Scriptのタブを閉じる。
3. スプレッドシートの「拡張機能」をクリックする。
4. 「Apps Script」から開き直す。
5. setupTriggerを再実行する。

改善しない場合は、Apps Scriptの実行ログを確認し、最初に発生しているエラーの内容を確認する。

### 17.3 フォルダIDに関するエラー

**考えられる原因**

- フォルダIDが正しく入力されていない。
- Google Driveのフォルダが削除されている。
- 保存先フォルダへのアクセス権限がない。

**対処方法**

1. Google Driveの画像保存用フォルダを開く。
2. URLからフォルダIDを取得し直す。
3. Apps ScriptのFOLDER_IDを書き換える。
4. コードを保存する。
5. setupTriggerを再実行する。

### 17.4 メールが登録されない

以下の項目を確認する。

| 確認項目 | 正しい状態 |
|---|---|
| Googleアカウント | GASとGmailで同じアカウントを使用している |
| メール件名 | 【お問い合わせ】から始まっている |
| 受付番号 | 空欄ではない |
| 受付日時 | 指定された形式で記載されている |
| 送信元 | SENDER_EMAILの設定と一致している |
| 重複 | 同じ受付番号が登録されていない |
| 検索期間 | 過去30日以内のメールである |
| トリガー | 正常に設定されている |
| フィルタ | 登録された行が非表示になっていない |
| エラーログ | 処理エラーが発生していない |

確認後、importGmailToSheetを手動で実行する。

### 17.5 添付画像が保存されない

以下の項目を確認する。

- フォルダIDが正しいか。
- 保存先フォルダへの書き込み権限があるか。
- JPGまたはJPEG形式の画像か。
- メールに実際の画像ファイルが添付されているか。
- 画像ファイルが破損していないか。
- 拡張子だけをJPGに変更した別形式の画像ではないか。

本文にファイル名を書いただけでは保存されない。

また、登録済みの受付番号のメールに画像を追加して再送しても、重複防止によって登録されない。

### 17.6 自動実行されない

1. Apps Scriptを開く。
2. 左側の「トリガー」をクリックする。
3. importGmailToSheetのトリガーが存在するか確認する。
4. トリガーが存在しない場合はsetupTriggerを再実行する。
5. 左側の「実行数」から実行履歴を確認する。

実行履歴では、実行日時、実行時間、成功・失敗などを確認できる。

### 17.7 エラーログが増え続ける

登録に失敗したメールは次回の自動実行時に再処理される。

受付番号がないメールや不正な日時が記載されたメールが残っている場合、実行のたびにエラーログが追加される。

テスト用の不正なメールについては、動作確認終了後にゴミ箱へ移動する。

実際の問い合わせメールについては、原因を確認し、必要な情報を補って対応する。対応が済む前にメールを削除しないこと。

## 18. 設定の変更方法

### 18.1 カテゴリを追加する

コード上部のDROPDOWNSという設定項目を確認する。

カテゴリの選択肢に新しい項目を追加する。

例えば「返品・交換」を追加する場合は、カテゴリの配列に以下の項目を追加する。

```javascript
'返品・交換'
```

変更後、コードを保存してsetupTriggerを再実行する。

### 18.2 担当部署を追加する

DROPDOWNSの担当者の選択肢を変更する。

例えば「商品管理担当」を追加する場合は、担当の配列に以下の項目を追加する。

```javascript
'商品管理担当'
```

変更後、コードを保存してsetupTriggerを再実行する。

既存の問い合わせ情報を保持したまま、プルダウンの選択肢を更新できる。

### 18.3 自動実行間隔を変更する

CONFIG内のINTERVALを変更する。

1分ごとに実行する場合：

```javascript
INTERVAL: 1,
```

5分ごとに実行する場合：

```javascript
INTERVAL: 5,
```

10分ごとに実行する場合：

```javascript
INTERVAL: 10,
```

変更後、コードを保存してsetupTriggerを再実行する。

### 18.4 自動実行を停止する

1. Apps Scriptを開く。
2. 左側の「トリガー」をクリックする。
3. importGmailToSheetの右側にあるメニューをクリックする。
4. 「トリガーを削除」をクリックする。

これにより定期的な自動実行が停止する。

手動でのメール取得は引き続き使用できる。

### 18.5 自動実行を再開する

1. Apps Scriptを開く。
2. 関数選択欄からsetupTriggerを選択する。
3. 「実行」をクリックする。
4. トリガーが再作成されていることを確認する。

## 19. 複数人で使用する場合の設定

### 19.1 スプレッドシートを共有する

1. 問い合わせ管理システムのスプレッドシートを開く。
2. 画面右上の「共有」をクリックする。
3. 担当者のGoogleアカウントのメールアドレスを入力する。
4. 必要な権限を設定する。
5. 共有する。

管理表を更新する担当者には編集権限を付与する。

閲覧だけを行う担当者には閲覧権限を付与する。

### 19.2 画像保存用フォルダを共有する

1. Google Driveを開く。
2. 「問い合わせ添付画像」フォルダを右クリックする。
3. 「共有」をクリックする。
4. 必要な担当者を追加する。
5. 必要な権限を設定する。

スプレッドシートを共有しただけでは、画像を閲覧できない場合がある。

画像を確認する担当者には、画像保存用フォルダへのアクセス権限も付与する。

### 19.3 自動実行を管理するアカウント

自動実行は、トリガーを作成したGoogleアカウントの権限で実行される。

複数人がそれぞれsetupTriggerを実行すると、複数のトリガーが作成される可能性がある。

そのため、自動実行を管理するアカウントを1つに決め、原則としてそのアカウントで初期設定やトリガーの変更を行う。

## 20. 運用上の注意事項

### 20.1 個人情報の管理

問い合わせ管理表には、お客様名、メールアドレス、注文番号などの個人情報が含まれる。

添付画像にも個人情報が含まれる可能性がある。

スプレッドシートやGoogle Driveのフォルダを一般公開せず、業務上必要な担当者にのみアクセス権限を付与する。

### 20.2 メール形式の統一

メール本文の解析は、指定された項目名と形式を前提としている。

問い合わせフォームのメール形式が変更された場合は、GASのメール解析処理も変更する必要がある。

### 20.3 メールの取得期間

現在の設定では、過去30日以内のメールを検索する。

システムを長期間停止した場合、30日より前のメールは自動登録されない可能性がある。

### 20.4 登録済みデータの削除

重複登録の判定には、管理表に保存されている受付番号とメールIDを使用している。

登録済みの行を削除すると、元のメールが検索対象期間内に残っている場合は再登録される可能性がある。

対応が完了した問い合わせは削除せず、ステータスを「完了」に変更することを基本とする。

### 20.5 自動ソート

新規メールが登録された際に、受付日時の新しい順に自動ソートされる。

複数人が同時に編集する場合は、作業中に行が移動する可能性がある。

必要に応じてAUTO_SORTをfalseに変更する。

### 20.6 エラーログの確認

メール取得処理が正常に動作しているか確認するため、定期的にエラーログを確認する。

スプレッドシートへのアクセス自体に失敗した場合など、エラーログシートに記録できないこともある。

その場合はApps Scriptの実行履歴を確認する。

### 20.7 Googleサービスの利用上限

Gmail、Google Drive、Google Apps Scriptには利用上限が設定されている。

大量の問い合わせメールや添付画像を処理する場合は、実行時間、メール取得回数、ストレージ容量などを考慮する必要がある。

### 20.8 自動化の対象範囲

現在のシステムは、問い合わせメールの転記と添付画像の管理を自動化するものである。

以下の業務は自動化していない。

- 問い合わせ内容のAI要約
- カテゴリの自動判定
- 緊急度の自動判定
- FAQの自動選択
- 担当部署の自動判定
- お客様への自動返信
- 担当部署への自動連絡

これらは担当者が問い合わせ内容を確認したうえで実施する。

## 21. 作成手順のまとめ

1. Google Driveに「問い合わせ添付画像」フォルダを作成する。
2. 作成したフォルダのIDを取得する。
3. Googleスプレッドシートを新規作成する。
4. スプレッドシートの名前を「問い合わせ管理システム」に変更する。
5. 拡張機能からApps Scriptを開く。
6. 初期コードをすべて削除する。
7. GASのプログラム完全版を貼り付ける。
8. FOLDER_IDに取得したフォルダIDを設定する。
9. 必要に応じて自動実行間隔を設定する。
10. コードを保存する。
11. setupTriggerを選択して実行する。
12. Googleアカウントへのアクセス権限を許可する。
13. 問い合わせ管理シートとエラーログシートが作成されていることを確認する。
14. Gmailからテストメールを送信する。
15. importGmailToSheetを実行する。
16. 問い合わせ情報が正常に登録されていることを確認する。
17. Google Driveに添付画像が保存されていることを確認する。
18. 管理表の画像リンクから画像を開けることを確認する。
19. トリガーが設定されていることを確認する。
20. 別のテストメールを送信し、自動登録されることを確認する。
21. プルダウン、色分け、ソート、フィルタなどの動作を確認する。
22. 空欄、重複、エラーなどの例外処理を確認する。
23. 必要な担当者に管理表と画像保存用フォルダを共有する。

以上の手順により、Gmail、Googleスプレッドシート、Google Drive、Google Apps Scriptを連携した問い合わせ管理自動化システムを構築できる。

実際の業務で使用する前に、利用するGoogleアカウントの環境で総合動作テストを実施すること。
