# Gmail問い合わせ管理自動化システム 作成・運用手順書

最新版（18列・カテゴリ自動入力・複数画像形式・対応待ち時間・元メールリンク対応）
対象プログラム：gmail_inquiry_improved.txt（同内容の gmail_inquiry_apps_script(2).txt でも可）

## 1. システムの概要

### 1.1 目的

問い合わせ窓口の担当者が、メールに記載されたお客様情報や問い合わせ内容を手作業でスプレッドシートに転記している業務を自動化する。

これにより、以下の効果を期待する。

- 問い合わせ内容の転記作業の削減
- 入力ミスや転記漏れの防止
- 問い合わせ対応の迅速化
- 添付画像の一元管理
- 問い合わせ対応状況・対応待ち時間の可視化
- 元メールへの直接アクセスによる確認・返信作業の短縮
- 添付画像の保存失敗による問い合わせの取りこぼし防止

### 1.2 使用するサービス

| サービス | 用途 |
|---|---|
| Gmail | 問い合わせメールの受信 |
| Googleスプレッドシート | 問い合わせ情報の管理 |
| Google Drive | 添付画像の保存 |
| Google Apps Script（GAS） | メール取得、本文解析、自動登録 |
| 時間主導型トリガー | プログラムの定期実行 |

外部APIや生成AIを使用せず、Googleのサービスのみで構築する。通常のGoogleアカウントで作成可能である。ただし、各サービスの利用上限や組織の管理者設定に従う必要がある。

### 1.3 システムの処理の流れ

1. お客様が問い合わせフォームから問い合わせを送信する。
2. 問い合わせ窓口のGmailにメールが届く。
3. GASが5分ごとに対象メールを検索する。
4. メール本文から受付番号、受付日時、お客様情報、問い合わせの種類、問い合わせ内容などを抽出する。
5. 登録済みのメールIDと受付番号を確認する。
6. 問い合わせの種類をカテゴリへ変換する。
7. 問い合わせ本文を先に管理表の末尾へ登録し、ステータスを「未対応」に設定する。対応待ち時間の数式も登録する。
8. Gmailの元メール（スレッド）へのリンクを登録する。
9. 添付画像をGoogle Driveに保存し、管理表に画像リンクを登録する。
10. 画像保存に失敗した場合は、本文を残したまま添付画像欄に警告を表示し、エラーログに記録する。
11. 担当者が問い合わせ内容、カテゴリ、対応待ち時間を確認し、緊急度、対応区分、担当などを入力する。
12. 担当者が回答や専門部署への引き継ぎを行い、対応が終了したらステータスを「完了」にする。

自動ソートは初期設定で無効であり、既存行を自動的に移動させない。エラーが発生した場合は可能な限りエラーログに記録する。同じメールの同じエラーは重複記録しない。

### 1.4 研修用フォームについて

今回の研修用フォームでは、お名前、メールアドレス、お問い合わせの種類、お問い合わせ内容が必須入力であり、注文番号、商品名、写真の添付は任意である。受付番号と受付日時はメールテンプレート側で付与される前提とする。

研修用のサンプル画面は架空の会社のものであり、送信しても実際にはメールが送られない。動作確認ではGmailから自分自身へテストメールを送る。本手順書はフォーム自体の作成・送信処理の実装を対象としない。

## 2. システムの仕様

### 2.1 管理表の列構成

| 列 | 項目 | 入力方法 |
|---|---|---|
| A | 受付番号 | 自動入力 |
| B | 受付日時 | 自動入力 |
| C | お客様名 | 自動入力 |
| D | メールアドレス | 自動入力 |
| E | 注文番号 | 自動入力 |
| F | 商品名 | 自動入力 |
| G | 問い合わせ内容（要約） | 自動入力 |
| H | カテゴリ | 自動入力・プルダウンで修正可能 |
| I | 緊急度 | 手入力・プルダウン |
| J | 対応区分 | 手入力・プルダウン |
| K | 担当 | 手入力・プルダウン |
| L | ステータス | 初期値は未対応・プルダウン |
| M | FAQ番号 | 手入力 |
| N | 備考 | 手入力 |
| O | 添付画像 | 自動入力・画像リンク |
| P | メールID | 自動入力・非表示 |
| Q | 対応待ち時間 | 自動計算・色分け |
| R | 元メール | 自動入力・Gmailリンク |

A～H列およびO～R列はプログラムが自動入力する。P列は重複防止用のため非表示となる。I～N列は担当者が入力する。ただし、L列のステータスは新規登録時に「未対応」となる。H列は担当者が必要に応じて修正できる。

問い合わせ内容（要約）にはメールに記載された問い合わせ内容を登録する。AIによる要約は行わない。既存の列名は変更しない。

カテゴリは、お客様がフォームで選択した種類を次の対応表に従って変換する。

| フォームの選択項目 | H列のカテゴリ |
|---|---|
| 配送について | 配送関連 |
| 商品の傷・不具合 | 商品不良・破損 |
| 組み立て・使い方 | 組み立て・使い方 |
| 注文の変更・キャンセル | 注文変更・キャンセル |
| 店舗・在庫 | 店舗・在庫 |
| その他 | その他 |

以前のテスト用表記「配送関連」「商品不良・破損」「注文変更・キャンセル」にも対応する。未対応の種類や空欄の場合は、H列を空欄にして問い合わせ自体を登録し、エラーログに記録する。

### 2.2 実装機能

| 機能 | 内容 |
|---|---|
| メール自動取得 | Gmailから対象メールを取得する |
| 自動転記 | メール本文から必要な情報を抽出する |
| 定期実行 | 5分ごとに自動実行する |
| 手動実行 | 任意のタイミングでメールを取得する |
| カテゴリ自動入力 | フォームで選択された種類を対応表で変換する |
| 画像保存 | JPG・JPEG、PNG、WebP、HEIC・HEIF、GIF、BMP、TIFF・TIFをGoogle Driveに保存する |
| 画像保存失敗対策 | 画像ごとに処理し、失敗しても本文を残す。警告とエラーログを記録する |
| 画像リンク | 管理表から保存された画像を開く |
| 重複防止 | メールIDと受付番号で重複を判定する |
| 空欄対応 | 注文番号などが空欄でも登録する |
| 複数行対応 | 問い合わせ内容の改行を保持する |
| ソート | 専用メニューから手動で受付日時順に並べ替える（自動ソートは初期状態で無効） |
| フィルタ | 特定の条件で問い合わせを絞り込む |
| プルダウン | 手入力項目の表記揺れを防止する |
| 色分け | 緊急度やステータスに応じて色を変更する |
| 対応待ち時間 | 受付日時から現在までの経過時間を計算し、6時間・24時間を基準に色分けする |
| 元メールリンク | Gmailのスレッドを管理表から開く |
| エラー記録 | 処理エラーや画像保存の警告を記録する |
| エラー重複防止 | 同じメールID・処理内容・エラー詳細のログは追加しない |
| ログ記録失敗対策 | ログ記録自体の失敗は実行ログに出力する |
| 既存データ保護 | 登録済みの担当者入力内容を上書きしない |

### 2.3 プルダウンの選択肢

**カテゴリ**

- 配送関連
- 商品不良・破損
- 組み立て・使い方
- 注文変更・キャンセル
- 店舗・在庫
- その他

**緊急度**

- 高
- 中
- 低

**対応区分**

- FAQで回答
- 専門部署へ引き継ぎ

**担当**

- 窓口担当
- 配送センター担当
- 修理・アフターサービス担当

**ステータス**

- 未対応
- 対応中
- 完了

### 2.4 色分け

| 項目 | 値 | 背景色 |
|---|---|---|
| 緊急度 | 高 | 赤 |
| 緊急度 | 中 | 黄色 |
| 緊急度 | 低 | 緑 |
| ステータス | 未対応 | 赤 |
| ステータス | 対応中 | 黄色 |
| ステータス | 完了 | 緑 |
| 対応待ち時間 | 6時間未満 | 警告色なし |
| 対応待ち時間 | 6時間以上24時間未満 | 黄色 |
| 対応待ち時間 | 24時間以上 | 赤 |
| 対応待ち時間 | 対応済み | 緑 |
| 対応待ち時間 | 日時要確認 | 黄色 |

対応待ち時間はB列の受付日時から計算する。未対応・対応中は経過時間を表示し、完了は「対応済み」と表示する。休日・夜間を含む暦時間であり、初回返信までの時間や実際の作業時間、完了までの実績時間ではない。再計算設定は変更時および1分ごとである。

## 3. 事前準備

以下のものを準備する。

- Googleアカウント
- Gmail
- Google Drive
- Googleスプレッドシート
- GASのプログラム完全版
- 動作確認用のJPG・PNG画像（必要に応じて他形式の画像）
- 不正画像の動作確認用ファイル（テキストを保存して拡張子を.jpgに変更したもの）

初期設定とテストはすべて同じGoogleアカウントで作業すること。テストには架空の情報と個人情報を含まない画像を使用する。既存環境の更新の場合は、先に管理表とコードをバックアップする。

## 4. Google Driveの設定

### STEP 1：Google Driveを開く

以下のURLにアクセスする。

https://drive.google.com/drive/my-drive

Googleアカウントにログインする。

### STEP 2：画像保存用フォルダを作成する

1. Google Driveの画面左上にある「＋ 新規」をクリックする。
2. 「新しいフォルダ」をクリックする。
3. フォルダ名に「問い合わせ添付画像」と入力する。
4. 「作成」をクリックする。

このフォルダに問い合わせメールの添付画像が保存される。

### STEP 3：フォルダIDを取得する

1. 作成した「問い合わせ添付画像」フォルダをダブルクリックする。
2. ブラウザ上部のアドレスバーを確認する。

URLは以下のような形式になっている。

https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz

「folders/」より後ろの文字列がフォルダIDとなる。

上記の場合、フォルダIDは以下の部分である。

1AbCdEfGhIjKlMnOpQrStUvWxYz

URLに「?」が含まれる場合は、それ以降を除く。

実際に作成したフォルダのIDをコピーし、メモ帳などに保存する。

このIDは後ほどGASの設定で使用する。

---

## 5. Googleスプレッドシートの作成

### STEP 4：スプレッドシートを新規作成する

以下のURLにアクセスする。

https://sheets.google.com/

1. 「空白のスプレッドシート」をクリックする。
2. 画面左上の「無題のスプレッドシート」をクリックする。
3. ファイル名を「問い合わせ管理システム」に変更する。

この時点では、セルに項目名やデータを入力する必要はない。

管理表の項目名、列幅、色分け、プルダウンなどはプログラムによって自動設定される。

## 6. Google Apps Scriptの設定

### STEP 5：Apps Scriptを開く

1. 作成したスプレッドシートを開く。
2. 画面上部の「拡張機能」をクリックする。
3. 「Apps Script」をクリックする。
4. 新しいタブでApps Scriptの編集画面が開く。

### STEP 6：プロジェクト名を変更する

1. Apps Script画面左上の「無題のプロジェクト」をクリックする。
2. プロジェクト名を「問い合わせ管理自動化」に変更する。

### STEP 7：初期コードを削除する

画面左側に「コード.gs」というファイルがある。

初期状態では、以下のコードが入力されている。

function myFunction() {

}

コード編集欄をクリックし、Ctrl + Aでコードをすべて選択する。

BackspaceまたはDeleteキーを押して削除する。

### STEP 8：プログラムを貼り付ける

1. 別添の最新版「gmail_inquiry_improved.txt」（または同内容の「gmail_inquiry_apps_script(2).txt」）を開く。
2. Ctrl + Aでプログラムをすべて選択する。
3. Ctrl + Cでコピーする。
4. Apps Scriptのコード編集欄をクリックする。
5. Ctrl + Vでプログラムを貼り付ける。

一部分だけではなく、必ずプログラム全体をコピーすること。

以前のコードが存在する場合は、既存のコードをすべて削除してから貼り付ける。

## 7. プログラムの基本設定

### STEP 9：フォルダIDを設定する

コードの先頭付近にCONFIGという設定項目がある。

初期状態では以下のようになっている。

```javascript
const CONFIG = {
  SHEET_NAME: "問い合わせ管理",
  ERROR_SHEET_NAME: "エラーログ",

  // ★GoogleドライブのフォルダIDを入力
  FOLDER_ID: "",

  GMAIL_QUERY: 'subject:"お問い合わせ" newer_than:30d -in:trash -in:spam',
  SUBJECT_PREFIX: "【お問い合わせ】",

  // テスト時は空欄でOK
  SENDER_EMAIL: "",

  INTERVAL: 5,
  AUTO_SORT: false, // 担当者の入力中に行を移動させない
  WAIT_WARNING_HOURS: 6,
  WAIT_CRITICAL_HOURS: 24,
  TIMEZONE: "Asia/Tokyo"
};
```

FOLDER_IDの部分を、STEP 3で取得したフォルダIDに変更する。

変更前：

```javascript
FOLDER_ID: "",
```

変更後の例：

```javascript
FOLDER_ID: '1AbCdEfGhIjKlMnOpQrStUvWxYz',
```

実際に取得したフォルダIDを入力すること。

文字列を囲む引用符と、末尾のカンマは削除しない。

### STEP 10：その他の設定を確認する

| 設定項目 | 内容 |
|---|---|
| SHEET_NAME | 問い合わせ管理表のシート名 |
| ERROR_SHEET_NAME | エラーログのシート名 |
| FOLDER_ID | 添付画像の保存先フォルダID |
| GMAIL_QUERY | Gmailの検索条件 |
| SUBJECT_PREFIX | 対象メールの件名の先頭文字列 |
| SENDER_EMAIL | 対象メールの送信元アドレス |
| INTERVAL | 自動実行間隔（分） |
| AUTO_SORT | 新規登録時の自動ソートの有無（初期値false） |
| WAIT_WARNING_HOURS | 待ち時間の黄色表示の基準（初期値6時間） |
| WAIT_CRITICAL_HOURS | 待ち時間の赤色表示の基準（初期値24時間） |
| TIMEZONE | 使用するタイムゾーン |

テスト段階ではFOLDER_ID以外を変更する必要はない。

### 7.1 自動実行間隔を変更する場合

初期状態では5分ごとに実行される。

```javascript
INTERVAL: 5,
```

1分ごとに実行したい場合は以下に変更する。

```javascript
INTERVAL: 1,
```

設定可能な実行間隔は1、5、10、15、30分である。

デモンストレーションでは1分、通常運用では5分を目安とする。

設定変更後は、コードを保存してsetupTriggerを再実行する必要がある。

### 7.2 特定の送信元だけを対象にする場合

初期状態では、送信元メールアドレスを指定していない。

```javascript
SENDER_EMAIL: '',
```

実際の企業で運用する場合は、問い合わせフォームの送信元アドレスを指定する。

設定例：

```javascript
SENDER_EMAIL: 'form-noreply@company.example',
```

上記のアドレスは仮想企業のものであるため、実際の運用時には実在する送信元アドレスを指定する。

自分自身にテストメールを送信する場合は空欄にしておく。

### 7.3 自動ソートの設定

最新版では担当者の入力中に行が移動することを防ぐため、自動ソートを無効にしている。

```javascript
AUTO_SORT: false,
```

新規問い合わせは管理表の末尾に追加される。複数人で利用する場合はfalseのまま運用することを推奨する。

自動ソートが必要な場合はtrueに変更できるが、編集中の行が移動する可能性がある。手動ソートはfalseでも使用できる。

### 7.4 対応待ち時間の警告基準を変更する場合

初期値は以下のとおり。

```javascript
WAIT_WARNING_HOURS: 6,
WAIT_CRITICAL_HOURS: 24,
```

例えば黄色を3時間、赤色を12時間にする場合は、それぞれ3と12に変更する。黄色の基準は0以上、赤色の基準は黄色より大きくすること。

変更後は保存し、setupTriggerを再実行して条件付き書式を更新する。

### STEP 11：コードを保存する

画面上部の保存ボタンをクリックする。

または、Ctrl + Sを押して保存する。

今回のシステムではWebアプリとして公開する必要がないため、「デプロイ」ボタンを押す必要はない。

## 8. 初期設定の実行

### STEP 12：実行する関数を選択する

Apps Script画面上部に、実行する関数を選択するプルダウンがある。

プルダウンをクリックし、以下の関数を選択する。

setupTrigger

この関数は、管理表の初期設定と自動実行の設定を行う。

### STEP 13：初期設定を実行する

setupTriggerを選択した状態で、画面上部の「実行」をクリックする。

初回実行時にはGoogleアカウントへのアクセス権限の確認画面が表示される。

### STEP 14：アクセス権限を許可する

1. 「権限を確認」をクリックする。
2. 使用するGoogleアカウントを選択する。
3. 要求されているアクセス権限を確認する。
4. 自分で作成したプログラムであることを確認し、必要な権限を許可する。

「Googleで確認されていないアプリ」という警告が表示される場合がある。

自分で作成したプロジェクトであり、コードの内容を確認できている場合に限り、「詳細」からプロジェクトへの移動を選択し、権限の確認を続ける。

必要となる主な権限は以下のとおり。

| 権限 | 使用目的 |
|---|---|
| Gmail | 問い合わせメールの取得 |
| Google Drive | 添付画像の保存 |
| Googleスプレッドシート | 問い合わせ情報の登録 |
| Apps Script | 自動実行トリガーの作成 |

組織のGoogleアカウントでは、管理者によって権限が制限されている場合がある。

### STEP 15：実行結果を確認する

Apps Script画面下部の実行ログを確認する。

正常に実行された場合は、以下のような内容が表示される。

実行開始

初期設定完了

実行完了

赤色のエラーが表示された場合は、後述するエラー対処方法を確認する。最新版では保存先フォルダの確認に失敗しても、本文取り込み用の初期設定は継続するため、「初期設定完了」と表示されても保存先フォルダ確認のエラーがないか確認する。

### STEP 16：スプレッドシートを確認する

1. スプレッドシートのタブに戻る。
2. F5キーを押して画面を再読み込みする。
3. 画面下部のシート一覧を確認する。

以下の2つのシートが作成されていれば正常である。

- 問い合わせ管理
- エラーログ

問い合わせ管理シートにはA～R列の18項目が作成される。Q列に対応待ち時間、R列に元メールが追加される。エラーログはエラーが発生するまで空のシートである場合がある。

また、重複防止に使用するメールIDの列が作成されるが、通常は非表示となっている。

最初から存在している「シート1」は使用しないため、不要であれば削除してよい。

### 8.1 旧バージョンから更新する場合

1. 管理表と旧コードをバックアップする。
2. 既存のトリガーを一時停止し、処理が実行中でないことを確認する。
3. 既存のスプレッドシートのApps Scriptを開き、最新版のコードに全文を置き換える。
4. FOLDER_IDおよび必要なSENDER_EMAILなどの設定を引き継ぐ。
5. 保存して、同じ管理アカウントでsetupTriggerを実行する。
6. 既存のA～P列のデータが保持され、Q・R列が追加されていることを確認する。
7. importGmailToSheetを実行して新規メールを確認する。
8. スプレッドシートを再読み込みし、専用メニューとトリガーを確認する。

A～P列が既存の指定列と一致し、Q・R列が未使用なら、既存シートを削除する必要はない。Q・R列が別用途で使用されている場合は上書きを避けるため初期設定が停止するので、データをバックアップして移動先を検討する。

既存行のQ列は受付日時から計算される。R列はP列にメールIDがあり、元メールを取得できる場合に追加される。メールIDがない手入力行はR列が空欄のままとなる。既存のカテゴリや添付画像は自動で再分類・再保存されない。旧カテゴリ「店舗・在庫・その他」は必要に応じて担当者が修正する。

## 12. 問い合わせ管理表の使用方法

### 12.1 問い合わせ情報の確認

問い合わせ管理シートを開き、新しく登録された問い合わせを確認する。

受付番号、受付日時、お客様名、メールアドレス、注文番号、商品名、問い合わせ内容は自動入力されている。

新規問い合わせのステータスは「未対応」となっている。

### 12.2 カテゴリの確認・修正

H列のカテゴリには、フォームの「お問い合わせの種類」に対応する値が自動入力される（2.1の対応表参照）。担当者は内容を確認し、必要な場合のみプルダウンで修正する。

- 配送関連
- 商品不良・破損
- 組み立て・使い方
- 注文変更・キャンセル
- 店舗・在庫
- その他

H列が空欄の場合は、元メールとエラーログを確認し、適切なカテゴリを選択する。

### 12.3 緊急度の入力

I列の緊急度を選択し、問い合わせ内容に応じて高・中・低を設定する。

判断基準の例：

| 緊急度 | 判断基準 |
|---|---|
| 高 | 安全上の問題、使用できない商品、配送直前の変更など |
| 中 | 商品の傷、注文内容の変更、交換希望など |
| 低 | 営業時間、在庫、組み立て方法などの一般的な質問 |

緊急度に応じてセルの背景色が自動的に変化する。

### 12.4 対応区分の入力

J列の対応区分から、以下のいずれかを選択する。

- FAQで回答
- 専門部署へ引き継ぎ

FAQで解決できる問い合わせについては窓口担当者が回答する。

FAQだけでは解決できない問い合わせについては、専門部署へ引き継ぐ。

### 12.5 担当者の入力

K列の担当から、対応する部署を選択する。

- 窓口担当
- 配送センター担当
- 修理・アフターサービス担当

### 12.6 ステータスの変更

L列のステータスを対応状況に応じて変更する。

| ステータス | 内容 |
|---|---|
| 未対応 | まだ問い合わせへの対応を開始していない |
| 対応中 | 窓口または専門部署が対応している |
| 完了 | 必要な対応が終了している |

### 12.7 FAQ番号と備考の入力

M列に、回答や判断に使用したFAQ番号を入力する。

N列には、担当部署への引き継ぎ事項や対応内容を入力する。

### 12.8 入力例

ベッドフレームの脚が破損している問い合わせの場合、以下のように入力する。

| 項目 | 入力内容 |
|---|---|
| カテゴリ | 商品不良・破損 |
| 緊急度 | 高 |
| 対応区分 | 専門部署へ引き継ぎ |
| 担当 | 修理・アフターサービス担当 |
| ステータス | 対応中 |
| FAQ番号 | FAQ-06 |
| 備考 | 安全上の懸念があるため使用中止を案内し、担当部署へ引き継ぐ |

なお、実際に回答や引き継ぎを行った後にステータスや備考を更新する。

### 12.9 対応待ち時間の確認

Q列に受付日時からの経過時間が表示される。初期設定では6時間以上で黄色、24時間以上で赤色となる。対応中も経過時間は継続して表示される。完了に変更すると「対応済み」と表示される。

「日時要確認」と表示される場合は、受付日時が空欄または日時として認識されていないため、元メールを確認する。未来の日時は0から表示する仕様である。

待ち時間だけで優先順位を決めず、I列の緊急度も併せて確認する。安全に関する問い合わせは経過時間が短くても優先する。

### 12.10 添付画像と元メールの確認

O列のファイル名をクリックするとDriveの画像が開く。R列の「メールを開く」をクリックすると元メールのスレッドが開く。

画像欄に「⚠ 1件の添付を保存できませんでした。元メール・エラーログを確認」などと表示される場合は、元メールで添付を確認し、必要に応じて担当者が手動でDriveに保存してリンクを追加する。正常に保存された画像のリンクも同じセルに残る。

「添付確認中（残る場合は元メールを確認）」が処理終了後も残っている場合は、途中で処理が中断された可能性がある。元メールと実行履歴を確認する。本文登録済みの画像の自動再試行は行わない。

## 13. 管理表の便利機能

### 13.1 手動でメールを取得する

スプレッドシートを再読み込みすると、画面上部に「問い合わせ管理」という専用メニューが表示される。

1. 「問い合わせ管理」をクリックする。
2. 「今すぐメールを取得」をクリックする。
3. 処理が完了するまで待つ。

定期実行を待たずに、新しい問い合わせメールを取得できる。

### 13.2 受付日時で並べ替える

1. スプレッドシート上部の「問い合わせ管理」をクリックする。
2. 以下のいずれかを選択する。

- 受付日時：新しい順
- 受付日時：古い順

受付日時だけでなく、お客様情報、担当者、対応状況、画像リンク、対応待ち時間、元メールなども同じ行として並べ替えられる。手動ソートの際は他の担当者が編集中でないことを確認する。通常は新規登録時の自動ソートを行わない。

### 13.3 フィルタで絞り込む

各列の見出しにあるフィルタマークをクリックすると、特定の条件に該当する問い合わせだけを表示できる。

未対応の問い合わせだけを表示する場合：

1. L列のステータスのフィルタマークをクリックする。
2. 値によるフィルタを選択する。
3. 「未対応」だけにチェックを入れる。
4. 「OK」をクリックする。

緊急度の高い問い合わせだけを表示する場合：

1. I列の緊急度のフィルタマークをクリックする。
2. 「高」だけにチェックを入れる。
3. 「OK」をクリックする。

緊急度とステータスのフィルタを組み合わせることで、優先的に対応する必要がある問い合わせを確認できる。

複数人で利用する場合は、他の担当者の表示に影響しないよう、フィルタ表示の利用も検討する。

## 14. 対象メールの形式

### 14.1 件名の形式

件名は以下の形式とする。

【お問い合わせ】受付番号 問い合わせの種類

例：

【お問い合わせ】Q1119-11 商品の傷・不具合

件名が「【お問い合わせ】」から始まらない場合は登録対象外となる。

### 14.2 本文の形式

お問い合わせフォームから、新しいお問い合わせがありました。

受付番号：

受付日時：

お名前：

メールアドレス：

注文番号：

商品名：

お問い合わせの種類：

お問い合わせ内容：

各項目は原則として1行ずつ記載する。

問い合わせ内容は複数行でも登録可能である。問い合わせ内容は最後の入力項目とする。それ以降の「注文番号：」などは本文の一部として扱う。ただし、先頭が📎の行は添付ファイル表示行として本文の終了を判定するため、フォームの自由記述と添付表示行が混同しない形式にする。

### 14.3 受付日時の形式

受付日時は以下の形式で記載する。

2026/11/19 14:38

年、月、日、時、分を記載する。

管理表では「11/19 14:38」と表示されるが、内部では年を含めた日時として管理される。

### 14.4 対応するメール形式

| メールの状態 | 処理結果 |
|---|---|
| 全角コロン「：」を使用 | 正常登録 |
| 半角コロン「:」を使用 | 正常登録 |
| 項目名とコロンの間に空白 | 正常登録 |
| 本文中に注文番号・商品名の項目名を記載 | 本文として保持する |
| 注文番号が空欄 | 空欄で登録 |
| 商品名が空欄 | 空欄で登録 |
| 項目がダッシュのみ | 空欄で登録 |
| 問い合わせ内容が複数行 | 改行を保持して登録 |
| JPG画像が1枚 | 画像を保存する |
| JPG画像が複数枚 | すべての画像を保存する |
| JPEG画像が添付されている | 画像を保存する |
| 添付画像がない | 添付画像欄を空欄にする |
| PNG、WebP、HEIC・HEIF、GIF、BMP、TIFF・TIFが添付されている | 対応形式として保存する |
| PDFなどの非対応形式 | 本文を登録し、画像欄に警告・エラーログを記録する |
| 不正なJPG・PNGの先頭バイト | 本文は登録し、該当画像の保存失敗を記録する |
| 正常な画像と不正な画像が混在 | 正常な画像は保存し、失敗した画像を警告する |
| 未対応の問い合わせの種類 | H列は空欄で登録し、エラーログに記録する |
| 受付番号がない | エラーログに記録する |
| 受付日時が空欄 | B列は空欄、Q列は日時要確認 |
| 受付日時が不正 | エラーログに記録する |
| 受付番号が重複している | 登録しない |
| 同じメールを再取得する | 登録しない |
| 件名が対象外 | 登録しない |

添付画像は実際のファイル添付が対象で、本文に埋め込まれたインライン画像は対象外となる。JPG・PNGは代表的なファイルシグネチャを確認するが、すべての画像形式について完全な破損検査を行うわけではない。HEICなどは保存できても閲覧環境によってプレビューできない場合がある。

| 23 | 手入力後にメールを再取得する | 手入力内容が保持される |
| 24 | 手動でメール取得を実行する | 新規メールが登録される |
| 25 | 手動取得せず自動実行を確認する | 新規メールが自動登録される |
| 26 | 件名が対象外のメールを送信する | 登録されない |
| 27 | 不正なJPGを添付する | 本文は登録され、O列に警告・エラーログが記録される |
| 28 | 正常なPNGと不正なJPGを混在させる | 本文と正常画像のリンクが登録され、失敗分は警告される |
| 29 | 非対応形式（例：PDF）を添付する | 本文は登録され、警告とエラーログが記録される |
| 30 | 添付画像なし | O列が空欄になる |
| 31 | 受付日時を現在より約1時間前にする | Q列に経過時間が表示され、警告色なし |
| 32 | 受付日時を現在より約8時間前にする | Q列が黄色になる |
| 33 | 受付日時を現在より約26時間前にする | Q列が赤色になる |
| 34 | L列を対応中・完了に変更する | 対応中は待ち時間を表示し、完了は緑色で対応済みと表示する |
| 35 | R列の「メールを開く」をクリックする | 対応するGmailスレッドが開く |
| 36 | 既存の16列の管理表を最新版へ更新する | A～P列のデータが保持され、Q・R列が設定される |

### 15.1 追加機能の具体的なテストメール

以下の共通テンプレートを使い、下表に従って受付番号、日時、種類、内容、添付ファイルを変更する。件名の受付番号と種類も一致させる。テスト中の時刻に合わせ、6時間・24時間の境界から十分離れた日時を入力する。

**件名**

【お問い合わせ】QTEST-01 商品の傷・不具合

**本文**

お問い合わせフォームから、新しいお問い合わせがありました。

受付番号：QTEST-01

お名前：佐々木 美咲

| 受付番号（例） | 種類 | 受付日時の設定 | 添付ファイル | 主な確認内容 |

QTEST-06の問い合わせ内容は「配送予定時刻を教えてください。」、QTEST-07は「注文した商品の数量を変更したいです。」、QTEST-08は「法人で家具を購入する場合、見積書を発行できますか。」とする。QTEST-08の注文番号・商品名は空欄にする。

### 15.2 エラーログ重複防止のテスト

画像保存失敗とは別に、未登録のメールが再処理されるケースを確認する。共通テンプレートの受付番号をQTEST-09などの未使用番号に変更し、受付日時を「2026/11/32 15:00」に変更して送信する。添付は不要である。

1. importGmailToSheetを実行し、対象メールのエラーログが1件記録されることを確認する。
2. 再度importGmailToSheetを実行する。
3. 5分ごとの自動実行後も同じメール・同じ処理・同じエラー詳細のログが1件のままであることを確認する。
4. 問い合わせ管理表に対象メールが登録されていないことを確認する。

テスト終了後は不正日時のテストメールをゴミ箱へ移動してよい。実際の問い合わせメールは解決するまで削除しない。

## 16. エラーログの確認方法

処理中にエラーが発生した場合は、エラーログシートを確認する。

### 16.1 エラーログの列構成

| 列 | 項目 | 内容 |
|---|---|---|
| A | エラー発生日時 | エラーが発生した日時 |
| B | 受付番号 | 対象の受付番号 |
| C | メール件名 | 対象メールの件名 |
| D | メールID | 対象メールの識別情報 |
| E | 処理内容 | エラーが発生した処理 |
| F | エラー詳細 | エラーの具体的な内容 |

### 16.2 エラー発生時の動作

エラーの発生箇所によって動作が異なる。

| エラーの種類 | 管理表の動作 | 再処理 |
|---|---|---|
| 受付番号なし・不正日時 | 登録せずログに記録 | 検索対象期間内は次回も取り込みを試みる |
| 本文登録時の失敗 | 途中の登録内容を可能な範囲で取り消す | 未登録なら次回も取り込みを試みる |
| 画像保存失敗・非対応形式 | 本文は維持し、O列に警告を表示する | 画像だけの自動再試行は行わない |
| 元メールリンクの取得失敗 | 本文は維持し、エラーログに記録する | setupTriggerで空欄のリンクを再取得できる場合がある |
| 未知のカテゴリ | H列を空欄にして本文を登録する | 担当者がカテゴリを修正する |
| システム全体のエラー | 処理が停止する場合がある | 原因解消後に手動または自動実行する |

画像保存は本文の登録後に行われる。1枚の画像が保存できなくても、他の画像を引き続き処理する。保存できなかった画像は元メールを確認し、必要に応じて手動で保存する。

### 16.3 エラーログの重複防止

メールID・処理内容・エラー詳細がすべて一致するログが存在する場合、新しい行を追加しない。同じメールでも異なるエラーは記録される。メールIDが空欄のシステム全体のエラーは重複防止の対象外である。

ログの重複を防止しても、未登録のメールの再処理自体は継続する。一時的な原因が解消すれば、正常に登録される可能性がある。以前のバージョンで蓄積した重複ログは自動削除されない。必要に応じてバックアップを取って整理する。

### 16.4 エラーログの記録に失敗した場合

ログ記録処理には例外処理があり、記録自体に失敗した場合は元のエラーとログ記録失敗の内容をApps Scriptの実行ログへ出力する。処理の継続が可能な場合でも、エラーログシートに記録されない可能性があるため、実行履歴を併せて確認する。

## 17. エラー発生時の対処方法

### 17.1 既存シートの列構成が異なる

エラーメッセージの例：

Error: 既存シートの列構成が異なります：問い合わせ内容（要約）

**原因**

既存の問い合わせ管理シートの項目名や列の順番が、プログラムで指定している内容と一致していない。または追加先のQ・R列に別用途のデータが存在する。

**対処方法**

1. 管理表をバックアップし、必要に応じてトリガーを一時停止する。
2. 2.1の列構成と既存シートの見出しを照合する。
3. A～P列のデータの対応関係を確認し、見出しや順序を正しい状態に戻す。
4. Q・R列が別用途で使用されている場合は、データを安全な別の場所に移す。
5. setupTriggerを実行し、既存データと新規列を確認する。

単に旧版のA～P列から最新版に更新する場合、通常はシート名の変更や作り直しは不要である。

修復できない場合に限り、旧シートを「問い合わせ管理_旧」などに変更して新しい管理表を作る方法もある。ただし、新しい管理表には過去の受付番号とメールIDが存在しないため、過去30日分のメールが再登録される可能性がある。自動取り込みを停止した状態で旧データと手入力内容を移行し、重複防止情報を確認してから再開する。

### 17.2 シートが見つからない

エラーメッセージの例：

Exception: シート「1933042743」が見つかりませんでした

**考えられる原因**

シートの削除や変更、古いシート情報の参照など。

**対処方法**

1. スプレッドシートを再読み込みする。
2. Apps Scriptのタブを閉じる。
3. スプレッドシートの「拡張機能」をクリックする。
4. 「Apps Script」から開き直す。
5. setupTriggerを再実行する。

改善しない場合は、Apps Scriptの実行ログを確認し、最初に発生しているエラーの内容を確認する。

### 17.3 フォルダIDに関するエラー

**考えられる原因**

- フォルダIDが正しく入力されていない。
- Google Driveのフォルダが削除されている。
- 保存先フォルダへのアクセス権限がない。

**対処方法**

1. Google Driveの画像保存用フォルダを開く。
2. URLからフォルダIDを取得し直す。
3. Apps ScriptのFOLDER_IDを書き換える。
4. コードを保存する。
5. setupTriggerを再実行する。
6. 新しい画像付きテストメールで保存を確認する。

フォルダにアクセスできなくても、最新版は本文の登録を継続する。既に本文が登録された問い合わせの画像は、フォルダIDを修正しても自動で再保存されない。元メールから手動で保存する。

### 17.4 メールが登録されない

以下の項目を確認する。

| 確認項目 | 正しい状態 |
|---|---|
| Googleアカウント | GASとGmailで同じアカウントを使用している |
| メール件名 | 【お問い合わせ】から始まっている |
| 受付番号 | 空欄ではない |
| 受付日時 | 指定された形式で記載されている |
| 送信元 | SENDER_EMAILの設定と一致している |
| 重複 | 同じ受付番号が登録されていない |
| 検索期間 | 過去30日以内のメールである |
| メールの場所 | ゴミ箱・迷惑メールに入っていないか確認する |
| トリガー | 正常に設定されている |
| フィルタ | 登録された行が非表示になっていない |
| エラーログ | 処理エラーが発生していない |

確認後、importGmailToSheetを手動で実行する。

### 17.5 添付画像が保存されない

以下の項目を確認する。

- フォルダIDが正しいか。
- 保存先フォルダへの書き込み権限があるか。
- JPG・JPEG、PNG、WebP、HEIC・HEIF、GIF、BMP、TIFF・TIFのいずれかの拡張子か。
- メールに実際の画像ファイルが添付されているか（インライン画像は対象外）。
- 画像ファイルが破損していないか。JPG・PNGは先頭バイトの形式確認も行う。
- O列に警告や「添付確認中」が残っていないか。
- エラーログに非対応形式や保存失敗が記録されていないか。

本文にファイル名を書いただけでは保存されない。保存済み画像が開けない場合は、Driveの閲覧権限も確認する。HEICなどは保存できていてもプレビューできない場合がある。

本文が登録済みの場合、画像だけの自動再試行は行わない。R列の元メールリンクから画像を確認し、必要に応じて手動でDriveへ保存してO列にリンクを追加する。正常な画像の既存リンクは残すこと。同じ受付番号でメールを再送しても重複防止のため登録されない。

### 17.6 自動実行されない

1. Apps Scriptを開く。
2. 左側の「トリガー」をクリックする。
3. importGmailToSheetのトリガーが存在するか確認する。
4. トリガーが存在しない場合はsetupTriggerを再実行する。
5. 左側の「実行数」から実行履歴を確認する。

実行履歴では、実行日時、実行時間、成功・失敗などを確認できる。

### 17.7 エラーログが増え続ける

同じメールID・処理内容・エラー詳細の組み合わせは1回だけ記録する仕様である。次の点を確認する。

1. 最新版のコードが保存されているか確認する。
2. エラーログのD～F列を比較し、同じ組み合わせか確認する。
3. メールIDが空欄のシステム全体のエラーであれば、重複防止対象外なので元の原因を解消する。
4. 過去に記録された重複行は自動では消えない。必要に応じて整理する。

ログを削除した場合、原因が解消されていない未登録メールについては次回の処理で再び1件記録されることがある。テスト用の不正メールは確認後にゴミ箱へ移動してよい。実際の問い合わせは対応が済む前に削除しない。

### 17.8 カテゴリが空欄になる

フォームの種類が2.1の対応表と一致しているか、本文に「お問い合わせの種類：」が存在するかを確認する。フォームの選択肢が変更された場合はgetCategoryとDROPDOWNSの設定を更新する。既存行は担当者が修正する。

### 17.9 対応待ち時間が表示されない・色が変わらない

1. B列の受付日時が日付と時刻として認識されていることを確認する。
2. L列が「完了」の場合は「対応済み」になる仕様である。
3. Q列の数式を削除していないか確認する。
4. CONFIGのWAIT_WARNING_HOURSとWAIT_CRITICAL_HOURSを確認する。
5. スプレッドシートのタイムゾーンが日本、再計算設定が変更時および1分ごととなっているか確認する。
6. 必要に応じてsetupTriggerを再実行し、数式と条件付き書式を再設定する。

### 17.10 元メールのリンクが空欄・開けない

1. P列にメールIDが記録されているか確認する（通常は非表示）。
2. 元メールがGmailに残っているか確認する。
3. 該当するメールボックスへアクセスできるGoogleアカウントで開く。
4. リンクが空欄の場合は、管理アカウントでsetupTriggerを再実行する。

手入力で登録された古い行など、メールIDがないものは元メールリンクを自動生成できない。スプレッドシートを共有してもメールボックスへのアクセス権限は付与されない。

## 18. 設定の変更方法

### 18.1 カテゴリを追加する

フォームの選択肢を追加する場合は、コード上部のDROPDOWNSのH配列とgetCategory関数の対応表の両方を変更する。

例えばフォームの「返品・交換について」を管理表の「返品・交換」として登録する場合、DROPDOWNSのH配列に以下の項目を追加する。

```javascript
"返品・交換"
```

次にgetCategory関数内のcategoryMapの配列に以下を追加する。

```javascript
["返品・交換について", "返品・交換"]
```

既存の配列要素との間にカンマが必要である。変更後は保存してsetupTriggerを再実行する。新規メールでカテゴリ自動入力を確認する。既存行のカテゴリは上書きされない。

### 18.2 担当部署を追加する

DROPDOWNSの担当者の選択肢を変更する。

例えば「商品管理担当」を追加する場合は、担当の配列に以下の項目を追加する。

```javascript
'商品管理担当'
```

変更後、コードを保存してsetupTriggerを再実行する。

既存の問い合わせ情報を保持したまま、プルダウンの選択肢を更新できる。

### 18.3 自動実行間隔を変更する

CONFIG内のINTERVALを変更する。

1分ごとに実行する場合：

```javascript
INTERVAL: 1,
```

5分ごとに実行する場合：

```javascript
INTERVAL: 5,
```

10分ごとに実行する場合：

```javascript
INTERVAL: 10,
```

変更後、コードを保存してsetupTriggerを再実行する。

### 18.4 自動実行を停止する

1. Apps Scriptを開く。
2. 左側の「トリガー」をクリックする。
3. importGmailToSheetの右側にあるメニューをクリックする。
4. 「トリガーを削除」をクリックする。

これにより定期的な自動実行が停止する。

手動でのメール取得は引き続き使用できる。

### 18.5 自動実行を再開する

1. Apps Scriptを開く。
2. 関数選択欄からsetupTriggerを選択する。
3. 「実行」をクリックする。
4. トリガーが再作成されていることを確認する。

### 18.6 対応待ち時間の基準を変更する

7.4を参照し、WAIT_WARNING_HOURSとWAIT_CRITICAL_HOURSを変更する。保存後にsetupTriggerを再実行する。

### 18.7 自動ソートの設定を変更する

CONFIG内のAUTO_SORTを変更する。falseが初期値であり、複数人での運用ではfalseを推奨する。コードを保存すると次回実行から反映される。

## 19. 複数人で使用する場合の設定

### 19.1 スプレッドシートを共有する

1. 問い合わせ管理システムのスプレッドシートを開く。
2. 画面右上の「共有」をクリックする。
3. 担当者のGoogleアカウントのメールアドレスを入力する。
4. 必要な権限を設定する。
5. 共有する。

管理表を更新する担当者には編集権限を付与する。

閲覧だけを行う担当者には閲覧権限を付与する。

### 19.2 画像保存用フォルダを共有する

1. Google Driveを開く。
2. 「問い合わせ添付画像」フォルダを右クリックする。
3. 「共有」をクリックする。
4. 必要な担当者を追加する。
5. 必要な権限を設定する。

スプレッドシートを共有しただけでは、画像を閲覧できない場合がある。

画像を確認する担当者には、画像保存用フォルダへのアクセス権限も付与する。

### 19.3 自動実行を管理するアカウント

自動実行は、トリガーを作成したGoogleアカウントの権限で実行される。

複数人がそれぞれsetupTriggerを実行すると、複数のトリガーが作成される可能性がある。

そのため、自動実行を管理するアカウントを1つに決め、原則としてそのアカウントで初期設定やトリガーの変更、手動のメール取得を行う。別のアカウントが手動取得を実行すると、そのアカウントのGmailが検索対象となる。

### 19.4 元メールの閲覧権限

元メールリンクは問い合わせを受信したGmailスレッドを開く。スプレッドシートや画像保存フォルダの共有だけではGmailへのアクセス権限は付与されない。組織の許可されたメール委任など、適切な運用で担当者が元メールを確認できるようにする。アカウントのパスワードを共有しないこと。

## 20. 運用上の注意事項

### 20.1 個人情報の管理

問い合わせ管理表には、お客様名、メールアドレス、注文番号などの個人情報が含まれる。

添付画像にも個人情報が含まれる可能性がある。

スプレッドシートやGoogle Driveのフォルダを一般公開せず、業務上必要な担当者にのみアクセス権限を付与する。

### 20.2 メール形式の統一

メール本文の解析は、指定された項目名と形式を前提としている。

問い合わせフォームのメール形式が変更された場合は、GASのメール解析処理も変更する必要がある。

### 20.3 メールの取得期間

現在の設定では、過去30日以内のメールを検索する。

システムを長期間停止した場合、30日より前のメールは自動登録されない可能性がある。

### 20.4 登録済みデータの削除

重複登録の判定には、管理表に保存されている受付番号とメールIDを使用している。

登録済みの行を削除すると、元のメールが検索対象期間内に残っている場合は再登録される可能性がある。

対応が完了した問い合わせは削除せず、ステータスを「完了」に変更することを基本とする。

### 20.5 自動ソート

最新版はAUTO_SORTがfalseであり、新規問い合わせは管理表の末尾に追加される。担当者の入力中に自動的に行が移動しない。

専用メニューの手動ソートは使用できるが、他の担当者の編集が終了してから実行する。一部の列だけを並べ替えると情報の対応関係が崩れるため、行全体を対象とする専用ソート機能を利用する。

### 20.6 エラーログの確認

メール取得処理が正常に動作しているか確認するため、定期的にエラーログを確認する。

スプレッドシートへのアクセス自体に失敗した場合など、エラーログシートに記録できないこともある。

その場合はApps Scriptの実行履歴を確認する。

### 20.7 Googleサービスの利用上限

Gmail、Google Drive、Google Apps Scriptには利用上限が設定されている。

大量の問い合わせメールや添付画像を処理する場合は、実行時間、メール取得回数、ストレージ容量などを考慮する必要がある。

### 20.8 自動化の対象範囲

現在のシステムは、問い合わせメールの転記、フォームの選択内容に基づくカテゴリ入力、添付画像の管理、対応待ち時間の表示と元メールリンクの登録を自動化するものである。

以下の業務は自動化していない。

- 問い合わせ内容のAI要約
- 緊急度の自動判定
- FAQの自動選択
- 担当部署の自動判定
- お客様への自動返信
- 担当部署への自動連絡

これらは担当者が問い合わせ内容を確認したうえで実施する。

### 20.9 対応待ち時間の位置付け

待ち時間は受付から現在までの経過時間を表示する。完了日時は保存しないため、完了までの時間や初回返信時間の実績分析には使用できない。また、警告の色分けは通知メールを送るものではない。担当者が定期的に管理表を確認する。

### 20.10 既存行・自動入力列の扱い

A～H列・O～R列の自動入力情報をむやみに削除しない。H列は必要に応じて修正可能であり、L列は業務上の状態に合わせて変更する。メールID列を削除しない。Q列の数式、R列のリンク、管理表の見出しを保護する運用も検討する。

画像保存失敗やリンク取得失敗があった行は、元メールとエラーログを確認して対応する。本文が登録済みのため、画像保存失敗だけを理由に問い合わせ行を削除しない。

## 21. 作成手順のまとめ

1. Google Driveに「問い合わせ添付画像」フォルダを作成する。
2. 作成したフォルダのIDを取得する。
3. Googleスプレッドシートを新規作成する。
4. スプレッドシートの名前を「問い合わせ管理システム」に変更する。
5. 拡張機能からApps Scriptを開く。
6. 初期コードをすべて削除する。
7. GASのプログラム完全版を貼り付ける。
8. FOLDER_IDに取得したフォルダIDを設定する。
9. 必要に応じて自動実行間隔を設定する。
10. コードを保存する。
11. setupTriggerを選択して実行する。
12. Googleアカウントへのアクセス権限を許可する。
13. 問い合わせ管理シートとエラーログシートが作成されていることを確認する。
14. Gmailからテストメールを送信する。
15. importGmailToSheetを実行する。
16. 問い合わせ情報が正常に登録されていることを確認する。
17. Google Driveに添付画像が保存されていることを確認する。
18. 管理表の画像リンクから画像を開けることを確認する。
19. トリガーが設定されていることを確認する。
20. 別のテストメールを送信し、自動登録されることを確認する。
21. カテゴリ自動入力、プルダウン、色分け、手動ソート、フィルタなどの動作を確認する。
22. PNG・複数画像形式、画像保存失敗時の本文登録を確認する。
23. 対応待ち時間の表示・色分け、元メールリンクを確認する。
24. 空欄、重複登録、エラーログ重複防止などの例外処理を確認する。
25. 必要な担当者に管理表と画像保存用フォルダを共有し、元メールを閲覧する権限を確認する。

以上の手順により、Gmail、Googleスプレッドシート、Google Drive、Google Apps Scriptを連携した問い合わせ管理自動化システムを構築できる。

実際の業務で使用する前に、利用するGoogleアカウントの環境で総合動作テストを実施すること。
